# 09：实现前必须冻结的详细设计

## 本文的约束力

主题系统的高风险部分不是写一个菜单页，而是 target/profile 解析、FFat 默认资源、SD 掉电事务、不可信包读取、能力契约、内存预算和发布信任链的组合。它们若在编码途中才决定，会导致页面已迁移却没有可加载资源、包已安装却不能安全恢复、或某些 ESP32 target 被无意排除。

因此本文不是“编码时再决定”的待办清单。每个标记为**阻断实现**的项目都必须在对应模块开始编码前冻结，并记录：

- 决定内容与精确参数；
- 被放弃方案及其不适用原因；
- 负责人、适用的固件/SDK 版本、关联 source/target；
- 主机测试、ESP32 实机测试和故障注入证据；
- ADR 编号以及变更时的 `theme_api`、`capability_contract`、FFat header 或分区迁移规则。

本文仅适用于 ESP32。完整设备矩阵为 Tab5、T-Display P4 TFT、T-Display P4 AMOLED、T-LoRa Pager SX1262、T-LoRa Pager LR1121、T-Deck、T-Watch S3、T-Deck Pro A7682E 与 T-Deck Pro PCM512A。Linux、nRF52、Cardputer 与其他非 ESP32 平台不应进入本表的 target、预算、测试或发布结论。

## D-01：ESP32 target/profile 矩阵

### 冻结决定

`Esp32TargetThemeProfile` 是唯一的 target 真相来源。它输入编译 target、板级显示/输入配置、PSRAM/FFat/SD capability 和产品绑定，输出：

```text
target_id
product_profile_id
ux_pack_id
layout_profile_id
display(width, height, orientation, color_depth, panel_class)
input(touch, key, encoder, physical_back)
memory_budget_id
factory_theme_variant_id
sd_support / FS rules
capability_contract_id
```

Theme Runtime、`theme_pack.py`、FactoryThemeImageBuilder、Extensions 兼容性说明和 CI 都只能使用这个输出。不得让主题 manifest、板名字符串或泛化 `esp_idf` 默认值推导 target。

### 必须冻结的矩阵

| target/硬件变体 | 产品/UX 现状 | 需要冻结的 layout profile | 需要完整覆盖的呈现面 | 当前必须补齐的事实 |
| --- | --- | --- | --- | --- |
| Tab5 | `tab5_touch` + 当前 `compatibility` binding | `tab5_touch` | 触控 shell、AppCatalog、全部大屏 route、overlay、输入、Extensions。 | IDF runtime 输出、显示/输入/预算参数。 |
| P4 TFT | `t_display_p4_touch` | `p4_tft_touch` | 触控 shell、地图/GNSS、设置、网络、聊天、Extensions 与全部大屏 route。 | 面板资源格式、方向、缓存预算。 |
| P4 AMOLED | `t_display_p4_touch` | `p4_amoled_touch` | 与 P4 TFT 相同的能力/route 集合。 | 刷新、烧屏保护、色彩/资源格式、缓存预算。 |
| Pager SX1262 | `pager_compact` + 当前 `compatibility` binding | `pager_compact_sx1262` | 紧凑 shell、按键/焦点、该 target 可达的完整 route 和 overlay。 | IDF runtime 不可再返回泛化 `esp_idf`。 |
| Pager LR1121 | `pager_compact` + 当前 `compatibility` binding | `pager_compact_lr1121` | 与 Pager SX1262 同类呈现，按 feature capability 过滤。 | 无线差异影响的 FeatureFlags 与契约导出。 |
| T-Deck | `deck_full` + 当前 `compatibility` binding | `tdeck_full` | 横屏、键盘/编码器/触控输入、完整 route、shell 和 overlay。 | Arduino/IDF 一致传递 `ux_pack_id`、输入映射。 |
| T-Watch S3 | `watch_compact` + 当前 `compatibility` binding | `twatch_compact` | 表盘、chat-watch、通知、唤醒/屏保、全部可达 route。 | watch source 的 route/slot 导出与 FFat 资源变体。 |
| T-Deck Pro A7682E | `screen_240x320` mono，蜂窝能力 | `tdeck_pro_240x320_a7682e` | PageKind、蜂窝电话/SMS/Email/设置、键盘焦点、mono shell/Extensions。 | product composition、runtime config、UX/profile binding。 |
| T-Deck Pro PCM512A | `screen_240x320` mono，音频差异 | `tdeck_pro_240x320_pcm512a` | 与 A7682E 的 route 集合按 feature capability 过滤。 | product composition、runtime config、UX/profile binding、音频 FeatureFlags。 |

**验收**：每个 target 都能在启动早期输出一条不含敏感数据的诊断记录，显示 `target_id`、`ux_pack_id`、`layout_profile_id`、FFat/SD capability 和 contract hash。主机工具对同一 target 生成的 manifest 判断必须与设备完全一致。

## D-02：FFat `builtin.default` 与 rescue 的精确定义

### 冻结决定

- `builtin.default` 是当前 UI 的完整正式默认主题，位于 FFat `/trailmate/factory/themes/builtin.default/`。
- 每个 D-01 profile 都有与固件 ABI/contract 绑定的 factory variant；它覆盖该 profile 的全部 capability/route、shell、overlay、输入、表盘或 mono 页面。
- 应用固件包含能力、路由、Presenter、Renderer、Theme Runtime 和 rescue，但不包含日常 UI 的完整图标、字体、token、页面 layout 或第二套菜单资源。
- `FactoryThemeHeader` (`TMFH`) 绑定 UI ABI、contract SHA-256、核心文件 hash、factory root hash、key ID、签名和 factory generation。
- `rescue` 完全不读取 FFat/SD。它提供固定错误码、target/profile 摘要、恢复/刷写说明、重启和目标已有的受控维护入口；它不会自动格式化、删除用户文件或执行不可逆操作。

### 回退粒度

```text
外部主题的可选资源失效       → 使用 FFat 同 asset 的默认资源
外部主题某 route 的布局失效   → 该 route 使用 FFat 同 route 的默认模板
外部主题核心清单/签名失效     → 整个会话切换 FFat builtin.default
SD 拔出或外部 provider 读错   → 帧边界切换 FFat builtin.default
FFat header/核心文件/契约失效 → 进入独立 rescue
```

所有回退必须写入固定错误码、原主题 id/version/hash、route（若适用）和 generation；不得持久化正文、密钥、路径或其他敏感数据。

### 验收

- 每个 ESP32 target 在无 SD 情况下从 FFat 启动、遍历完整 route、重启并保持可用。
- FFat 挂载失败、`TMFH` CRC/签名/ABI/contract 错误、核心文件 hash 错误均进入 rescue。
- 外部主题删除、资源 hash 错误、layout 违反 slot、SD 拔出、激活失败后可回到 Dashboard、Settings、Extensions 与安全返回路径。
- 扩展包不能创建、覆盖、卸载或引用 `builtin.default` 命名空间。

## D-02a：App 与 FFat 的发布/更新配对

必须在 ADR 中选择下列一项，并在首个支持主题的正式发布前实现对应测试：

| 策略 | 精确规则 | 优点 | 必须证明的风险控制 |
| --- | --- | --- | --- |
| A：兼容性 App OTA + 配套维护刷写 | App OTA 仅在当前 `TMFH` 的 ABI/contract 明确兼容时允许；默认主题更新通过应用 + FFat 配套维护刷写。 | 不要求双 FFat 分区。 | OTA 前 header 检查、维护刷写步骤、任意中断不会留下可启动但不匹配的组合。 |
| B：双 App + 双 FFat 成对 OTA | 写入非活动 app/FFat 对，验证两镜像，写 `pending boot-pair`，重启自检后提交；任何失败回到旧对。 | 可通过 OTA 更新默认资源并保持掉电回滚。 | 分区容量、boot-pair state、bootloader 选择、迁移、任意阶段断电回滚。 |

无论采用哪一项，下载到 SD 的主题均不能替代、修复或覆盖 factory root。发布文件名、签名、生成规则、ABI/contract 兼容比较和恢复操作须在 FactoryThemeImageBuilder 中固定。

## D-03：SD 存储根、目录与扫描规则

```text
/trailmate/packs/
├── index/
│   ├── theme-index.a
│   ├── theme-index.b
│   ├── theme-state.a
│   └── theme-state.b
├── .tmp/
│   └── <txn-id>.tmt.part
├── .staging/
│   └── <txn-id>/payload/themes/<id>/...
└── themes/
    └── <theme-id>/versions/<semver>-<sha8>/
        ├── package.ini
        ├── theme.ini
        ├── theme.tmb
        ├── assets.index
        ├── assets/<asset-id>.bin
        └── fonts/<font-id>.bin
```

冻结规则：

- 外部主题只安装到该 SD 根；FFat factory root 是逻辑只读区域，运行时和 Extensions 无写入权限。
- `<theme-id>` 使用 `[a-z][a-z0-9]*(\.[a-z0-9-]+)*`；禁止 `builtin.`、`system.` 和其它保留前缀。
- `<semver>-<sha8>` 由已验证的 `package.ini` 与归档 SHA-256 导出，不能使用显示名称或 ZIP 内的任意路径。
- Theme Runtime 不递归扫描 `themes/`；唯一可信入口是双槽 `theme-index` 和 `theme-state`。`.tmp`、`.staging`、未知目录、作者源文件和 ZIP 均不是运行时资源来源。
- SD 重新插入后，必须重读有效索引并验证活动版本目录、头部和哈希；目录时间戳/旧缓存不能作为可信依据。
- 所有 ESP32 profile 均支持 SD 外部主题；若硬件配置实际没有可用 SD，能力目录必须将主题下载/安装 action 标为不可用，同时 FFat 默认 UI 仍完整可用。该硬件配置不能被列为“已支持 SD 主题”。

## D-04：掉电安全的安装、激活、更新与卸载事务

### 固定记录

`theme-state.a/b` 使用固定大小 `TMTS` 记录，至少包含：

```text
magic, format_version, generation, phase
current { id, version, archive_sha256 }
previous { id, version, archive_sha256 }
transaction_id, payload_sha256, failure_count, crc32
```

`theme-index.a/b` 使用 `TMIX` 头和固定记录，精确描述已提交版本。每次写入选择旧槽或无效槽，流程是：写完整记录 → 刷新平台缓存 → 读回 → 校验 CRC → generation 成为有效值。启动选择 CRC 正确且 generation 最大的槽。两个槽都无效时外部主题不可用，启动 FFat `builtin.default`；FFat 无效时进入 rescue。

### 事务状态与恢复

```text
NotInstalled
  → Downloading(.tmt.part)
  → ArchiveVerified
  → Extracting(.staging)
  → PayloadVerified
  → Indexed(version directory committed)
  → InstalledInactive
  → ActivationPending
  → ActiveCommitted

任一步失败：活动主题不变
新候选启用失败：RollbackPending → previous ActiveCommitted → FFat builtin.default
```

| 断点 | 启动恢复动作 | 允许的可见状态 |
| --- | --- | --- |
| 下载 `.part` | 依据事务记录删除或保留诊断文件；不写 theme index。 | 已提交主题或 FFat 默认。 |
| staging 解压/校验 | 忽略并按清理策略处理 staging；不写 theme index。 | 已提交主题或 FFat 默认。 |
| payload 验证完成、index 未提交 | 不将目录列为已安装；允许清理。 | 已提交主题或 FFat 默认。 |
| 已安装但未启用 | 保留 `installed_inactive`，不改变 active state。 | 当前 active 主题。 |
| `ActivationPending` | 重新验证候选；失败恢复 `previous`，再退 FFat。 | 先前 active 或 FFat 默认。 |
| `ActiveCommitted` 后发现读取/渲染错误 | 增加失败码/计数，在帧边界回退。 | previous 或 FFat 默认。 |

删除当前主题的固定流程是：激活 FFat `builtin.default` → 提交 state → 从 index 删除该主题记录 → 删除不被 current/previous 指向的版本目录 → 提交新 index。不得先删目录以腾出空间。

## D-05：`.tmt` 分发归档与签名

### 容器限制

- 容器为标准 ZIP，只接受 `Stored (0)` 与 `Deflate (8)`。
- 拒绝加密 ZIP、嵌套 ZIP、符号链接、绝对路径、`..`、反斜杠歧义、重复规范路径、未知压缩方式、未声明的 ZIP64/数据描述符变体。
- 根必须有唯一 `package.ini` 与 `signature/manifest.sha256`；payload 必须位于 `payload/themes/<id>/`。
- `manifest.sha256` 枚举每一个 payload 文件的规范路径、长度与 SHA-256；受保护发布 CI 的发布签名覆盖固定编码后的 manifest、package identity、精确 `target_profile_id` 与构建清单。
- 安装前和解压过程中检查归档大小、解压总量、文件数、单文件、像素/字体、压缩比、路径和签名。任一校验失败则删除 staging 或隔离归档，活动主题不变。

### profile 预算表

| profile | `.tmt` 压缩上限 | 解压后总量 | 文件数 | `theme.tmb` | 单资源 | 解压压缩比 |

| `pager_compact_sx1262` | 512 KiB | 768 KiB | 96 | 32 KiB | 16 KiB | 20:1 |

| `tdeck_full` | 512 KiB | 768 KiB | 96 | 32 KiB | 16 KiB | 20:1 |

| `tdeck_pro_240x320_a7682e` | 512 KiB | 768 KiB | 96 | 32 KiB | 16 KiB | 20:1 |

## D-06：设备侧文件、二进制格式和读取模型

| 文件 | 编码 | 读取时机 | 允许内容 |
| --- | --- | --- | --- |
| `package.ini` | UTF-8 行式 `key=value` | 安装、详情、索引 | 包身份、版本、作者、兼容性、用户可见短文本。 |
| `theme.ini` | UTF-8 行式 `key=value` | 加载、启用 | 核心版本、相对路径、profile/coverage 声明与预算。 |
| `theme.tmb` | 小端固定记录二进制 | 启用、route 打开 | token、布局、slot、资源引用、route 目录。 |
| `assets.index` | 小端固定记录二进制 | 启用、asset 打开 | asset 到路径/尺寸/hash/variant 的映射。 |
| `assets/*.bin`、`fonts/*.bin` | 已转换的 LVGL 数据 | 按需 | 经索引声明的图像、装饰、字体资源。 |

安装后的 payload 不允许 YAML、JSON、SVG、PNG、源代码、脚本、可执行程序或任意配置。作者源格式可以在 PC 使用 YAML/JSON/SVG/PNG；工具必须转换成上述设备格式。

主题读取的硬规则是：不构造 JSON DOM、cJSON、无界 `std::string`、`std::vector` 主题清单或递归 AST；不根据不可信长度分配栈数组；不把整包、整索引、整页字符串表读入内存。使用定长行缓冲、定长 POD record、固定页缓存和长期拥有的成员工作区。具体字节协议见 [10：有界流式读取与二进制索引协议](./10-有界流式读取与二进制索引协议.md)。

`theme.tmb` 的头部至少固定：magic、format major/minor、header size、total size、CRC32、contract SHA-256、target variant/profile ID、token/route/node/string/resource table offset 与 flags。设备必须在任何表读取前校验总长度、偏移、相加/相乘溢出、重叠表、未知必需 flags、节点循环和树深度。

## D-07：全量能力契约与受限布局 DSL

### 契约生成

固件构建必须导出一个版本化 SDK 目录，例如：

```text
theme-sdk/<capability-contract>/
├── capabilities.json             # 主机/文档用途
├── routes.json                   # 主机/文档用途
├── actions.json                  # 主机/文档用途
├── slots.json                    # 主机/文档用途
├── assets.json                   # 主机/文档用途
├── tokens.json                   # 主机/文档用途
├── targets.json                  # 全 ESP32 target/profile
├── route-test-fixtures.bin       # 设备/工具共享 fixture
└── contract.sha256
```

SDK 中的 JSON 仅存在于主机；设备使用其相应的固定记录导出物。契约生成器必须覆盖：启动、菜单、仪表盘、屏保、表盘、顶栏、overlay、所有 AppCatalog 项、所有 `PageKind`、蜂窝子页面、输入与恢复路径。每一项都含 route、slot、action、状态、危险级别、输入/焦点要求、专用 widget、target/profile 条件和弃用状态。

### DSL 允许集

```text
container: row, column, grid, stack, overlay, scroll, tabs, overflow
leaf:      slot, widget
property:  gap, padding, align, justify, grow, size-range,
           style_class, order, compact_visibility, accessibility_label
```

`widget` 只能引用固件 registry 中的 MapCanvas、SkyPlot、SettingsEditor、IME、SecretInput、ConfirmDialog、Progress、Pairing、CallOverlay 等固定类型，并只接受契约定义的参数。禁止表达式、条件语言、循环、脚本、动态字符串拼接、回调、URL、文件路径、数据筛选、业务排序规则、任意 LVGL 属性透传和主题自定义代码。

### 演进规则

- 新增可选 token/asset/slot 可提升 contract 次版本；旧主题明确回退到 FFat 同资源。
- 新增必需 slot/action、改变动作语义、删除/重用 ID 必须提升 contract 主版本；不兼容主题禁止启用。
- 每个被弃用 ID 都列出替代 ID、支持窗口和拒绝版本；工具会在 build 阶段给出明确迁移诊断。
- 每个外部主题对其声明 profile 必须覆盖该 profile 全部 route；`coverage=full` 是可安装 UI Theme Bundle 的固定规则。主题如只想替换令牌/资源，应使用单独的 `appearance-overlay` 包类型并不得改写 layout。

## D-08：每个 ESP32 profile 的资源、RAM、栈与性能预算

### 预算结构

每个 target profile 文件必须包含以下确切字段，并由工具、设备和 CI 共用：

```text
installed_theme_record_capacity
catalog_page_record_capacity
manifest_bytes / line_bytes / string_bytes
route_count / layout_node_count / tree_depth
theme_metadata_bytes / layout_work_buffer_bytes
asset_index_record_count / asset_cache_bytes / image_decode_bytes
font_page_bytes / open_file_handle_count
archive_bytes / extracted_bytes / file_count / per_file_bytes
ui_task_stack_delta = 0
activation_frame_budget_ms / page_open_budget_ms / boot_budget_ms
```

`ui_task_stack_delta = 0` 是硬要求：任何解析、解压、哈希、索引、布局或图像元数据处理都不得通过扩大 LVGL UI 任务栈来解决。使用后台任务、固定成员工作区、静态工作区或调用方提供的缓存，并符合仓库 ESP stack hygiene 规则。

### 必测性能场景

每个 ESP32 target/变体均以 `builtin.default` 与一个完整外部主题为对照，测量并冻结：

- 无 SD、SD 已安装但未启用、SD 外部主题已启用三种冷启动首屏时间；
- 菜单、聊天编辑、设置编辑、Extensions、地图/GNSS、对应 mono/蜂窝页和 watch page 的首次/再次打开时延；
- 主题启用、预览、回退、恢复默认时的最大帧停顿；
- 堆、PSRAM、UI 任务栈高水位、文件句柄、SD 读次数、缓存命中和长期切换后的碎片；
- SD 移除、读取错误、资源 hash 错误、FFat 头失配与激活掉电的恢复时间。

超过预算时，必须调整主题格式、资源转换、缓存或 profile 上限；不得关闭签名/hash/slot 校验，也不得增加 UI 任务栈规避问题。

## D-09：并发、缓存、资源句柄与 SD 热拔插

### 唯一写者规则

- UI/LVGL 所有者任务是唯一能创建、修改、删除 LVGL 对象和交换活动 Theme Provider 的任务。
- 下载、解压、哈希、签名和大文件读取在包安装后台路径执行，不持有 LVGL 对象。
- 后台只提交固定大小、可复制的“已验证主题候选”事件；UI 在帧边界接受或拒绝。
- 外部主题不能注册定时器、输入回调、网络回调或后台任务。

### 缓存与句柄规则

- asset cache 键为 `asset_id + theme_generation + profile_id`，采用固定槽或固定容量 LRU；每槽记录 owner/refcount/验证状态。
- generation 改变后旧 provider 不再为新页面提供句柄；对象析构、页面切换或 profile 切换按引用计数释放资源。
- 缓存满且无可回收槽时，使用 FFat 同 asset 的资源或根据 route fallback；禁止扩容。
- SD 移除/读错误事件到达后，Theme Runtime 立即标记外部 provider 无效，禁止新读；UI 在当前帧完成或受控安全点切换 FFat，并保留可解释诊断。
- SD 再插入须重新验证 index、state、manifest、layout header 和按需资源 hash；不信任旧内存缓存或目录时间戳。

## D-10：工程目录、CI 发布签名、侧载与撤销

### 信任链

```text
固件内置官方根公钥
  → 验证官方 TMCP catalog 签名
    → catalog 将 release_key_id 绑定受保护发布公钥/状态
      → 验证 .tmt 的 release 签名
        → 比对 catalog archive SHA-256
          → 验证归档 manifest.sha256
```

需要冻结签名算法（优先 Ed25519，或目标实测可用的等价方案）、规范字节序、key ID、根公钥轮换、受保护发布环境、撤销列表格式、过期策略、离线缓存期限与错误码。仅 SHA-256 不足以证明发布者身份。第三方作者通过工程 PR 提交源文件，发布包的身份由源提交、合并 PR 和 CI 构建证明共同建立。

### 侧载

侧载是否允许是产品安全决定，必须在 ADR 中写明下列之一：

| 政策 | 设备行为 |
| --- | --- |
| 仅可信发布侧载 | 用户从 SD/USB 选择 `.tmt`，但包必须由固件信任的发布 key 签名，并可在工程 Release/Pages 中找到同一构建记录；仍显示发布者与风险说明。 |

官方目录与侧载安装都必须遵守相同的 Theme Runtime 读取、资源、能力和回退边界。撤销后已安装主题的显示、禁用、恢复默认和离线行为也必须列入 Extensions 状态机。

## D-11：安装索引、版本保留、更新、回滚与卸载

`theme-index.a/b` 的固定记录至少持久化：主题 ID、版本、精确 `target_profile_id`、归档 SHA-256、安装时间、安装 generation、theme API、contract hash、验证状态、短显示名称、归档/解压字节和目录派生所需字段。活动状态总是记录精确 version/profile/hash，不能只记录 ID。

固定规则：

- 新版本总是写入新的 `<version>-<sha8>` 目录，不能原地覆盖当前或 previous 版本。
- 安装完成后状态是 `installed_inactive`；激活必须由用户在 Extensions 明确选择，或由用户明确批准的自动更新策略触发。
- 新活动版本跨重启且全 route 自检成功前，previous 版本不得清理。
- 回滚只写 state 指向已验证 previous，不重新下载；空间不足时先拒绝更新并给出可删除候选，不能删除活动版本腾空间。
- 卸载当前主题须先切换 FFat `builtin.default` 并提交，再删除所有不被 previous 指向的目录和索引记录。
- 任何索引/状态异常都按 D-04 恢复，不扫描 SD 目录猜测主题。

## D-12：测试、发布与开放第三方的门槛

### 编码前可以完成的设计验证

- 在每个 ESP32 target 的真实 SD/FAT 环境测量写入、刷新、掉电、重新挂载和 rename 行为；不从 Linux 推断。
- 在目标 ESP 构建验证 ZIP Store/Deflate、选定签名算法、TLS/目录签名、代码大小、堆与错误处理。
- 自动导出现有 UI 目录，复核 [02](./02-界面能力目录与稳定契约.md) 和 [13](./13-当前UI源码盘点与解耦改造地图.md) 没有遗漏 route/overlay/PageKind/蜂窝/表盘。
- 测量当前各目标 UI 任务栈、堆、PSRAM、FFat 和 SD 基线，确认 D-05/D-08 的数值。
- 为 FFat `builtin.default` 的所有 route 与 rescue 建立截图、输入、动作、回退和故障基线。

这些工作产出实验报告、fixture 和 ADR，不应演变成未冻结协议下的主题加载实现。

### 代码合并与用户开放前的硬性验证

1. 全部 ESP32 target/变体在无 SD、FFat 正常时启动完整 `builtin.default`；FFat 异常时进入 rescue。
2. 完整 route 目录中的每项均通过必需 slot、动作、焦点、输入、长文本、RTL、可读性、目标 profile 命中区和危险确认测试。
3. 下载、侧载、安装、预览、启用、更新、回退、恢复默认、卸载和撤销不会破坏当前可用主题。
4. 下载、解压、索引、state、启用、App/FFat 更新的每个持久化点掉电后，重启都能进入 FFat 默认或 rescue。
5. 路径穿越、ZIP bomb、重复路径、超限资源、坏 CRC/SHA/签名、未知版本、节点循环、未知 widget 被拒绝且有固定错误码。
6. SD 运行中拔出不崩溃、不阻塞 UI，并回退 FFat；FFat 核心资源异常进入 rescue。
7. 主题 reader、renderer、安装器不违反 ESP 栈卫生；检查不含 JSON DOM、无界容器或变长栈数组。
8. 每一个 target/profile 有实机性能报告、故障注入报告、兼容矩阵、截图/视频和可复现 `.tmt`/FFat 镜像构建记录。
9. 官方目录的发布 key、CI 签名、撤销、过期、投诉和安全通告流程已经演练。
