# 08：FFat 出厂默认主题与 SD 加载协议

## 必须先确认的产品规则

Trail Mate 当前已经实现并正在使用的界面，必须作为随固件发布的**出厂默认主题**持续存在。建议给它一个保留 ID：

```text
builtin.default
```

它不是一个要由扩展中心下载的包，也不是首次安装主题后可以删除的“旧 UI”。完整默认主题的图标、视觉令牌、布局二进制和资源索引不放进应用固件镜像，而是随出厂 FFat 镜像写入内部 Flash 的 FFat 分区。它就是 **FFat 正常时** 设备在下列任何条件下必定使用的完整默认界面：

- 用户从未安装或启用过主题；
- SD 卡不存在、未挂载、只读、空间不足、损坏或被拔出；
- Extensions 目录不可访问、网络不可用、下载失败或归档校验失败；
- 外部主题与当前固件、精确 `target_profile_id` 或内存档位不兼容；
- 外部主题的清单、布局二进制、资源索引或图标资源损坏；
- 用户在 Extensions 选择“恢复默认主题”；
- 主题启用事务中断，或主题导致加载/渲染自检失败；
- 启动时发现上一次主题切换未完成。

因此，主题系统的正确关系是：

```text
固件镜像         = 能力、路由、动作、渲染器、加载器 + 极小 rescue
FFat 出厂主题    = builtin.default 的图标、令牌、布局和资源索引
外部 SD 主题     = 在 FFat 默认主题的能力壳上受约束地覆盖图标、令牌和布局
```

外部主题无法覆盖 `builtin.default` 的能力、导航、动作、故障恢复或安全模式入口；即使视觉上完全不同，业务界面仍由内置能力壳构造。

## 存储模型

### 固件镜像中的内容

```text
Firmware image
├── 所有 UI 能力壳、动作、路由、焦点和回退逻辑
├── Theme Runtime
│   ├── FFat / SD 挂载与主题注册表
│   ├── theme.ini / theme.tmb / assets.index 验证器
│   └── 外部主题覆盖层与恢复逻辑
└── rescue 呈现
    └── 只显示“FFat 默认主题不可用/恢复/刷写”诊断，不含完整主题资源
```

### FFat 出厂主题内容

```text
FFat
└── /trailmate/factory/
    ├── factory-theme.header             # 固定大小、签名/CRC 的 FactoryThemeHeader
    └── themes/builtin.default/
        ├── package.ini
        ├── theme.ini
        ├── theme.tmb
        ├── assets.index
        └── assets/*.bin
```

`builtin.default` 不消耗 SD 空间，不进入 `theme-index.a/b`，不显示为可卸载包，也不能由名为 `builtin.default` 的第三方归档替换。主题注册表必须把该 ID 视为保留字。`factory-theme.header` 绑定预期 Theme API、能力契约哈希、FFat 资源版本和清单/核心文件哈希；详细格式和 FFat 镜像更新规则见 `11`。

### SD 卡中的外部主题

所有可下载或侧载的 `theme-bundle` 都安装到 SD。其规范路径为：

```text
/trailmate/packs/
├── index/
│   ├── installed.json
│   ├── theme-index.a                   # 固定大小、带 CRC 的主题安装索引快照
│   ├── theme-index.b                   # 固定大小、带 CRC 的主题安装索引快照
│   ├── theme-state.a                   # 固定大小、带 CRC 的活动主题记录
│   └── theme-state.b                   # 固定大小、带 CRC 的活动主题记录
├── .tmp/
├── .staging/
└── themes/
    ├── acme.forest/
    │   └── versions/
    │       └── 1.2.0-a1b2c3d4/
    │           ├── theme.ini
    │           ├── theme.tmb
    │           ├── assets.index
    │           ├── assets/*.bin
    │           └── fonts/*.bin         # 可选且受预算限制
    └── another.publisher.theme/
        └── versions/<version>-<sha8>/...
```

主题归档的身份由 `package.ini` 中的 `id` 决定，安装器必须验证它与 `payload/themes/<theme-id>/` 中的 `<theme-id>` 相同。目录名不能来自用户可控的展示名称；必须由已校验的规范主题 ID 得出，防止路径穿越和名称冲突。主题运行时仅使用 `theme-index.a/b` 与 `theme-state.a/b`；同目录的 `installed.json` 仍可为已有的其他包类型保留，但主题读取路径不得解析它。

## 运输格式与安装格式

主题在三个阶段使用三种不同形式，不能混淆：

| 阶段 | 文件/格式 | 是否由固件直接渲染 | 用途 |
| --- | --- | --- | --- |
| 作者工程 | `theme.yaml`、SVG、PNG、预览截图 | 否 | 供主题作者编辑，主机工具输入。 |
| 分发运输 | `<id>-<version>-<target-profile-id>.tmt`，ZIP 容器 | 否 | 供与精确 profile 对应的扩展目录下载、USB/SD 侧载和安装器校验。 |
| FFat 出厂负载 | `theme.ini`、`theme.tmb`、`assets.index`、`*.bin` | 是 | `builtin.default` 的完整默认资源，由 FFat 镜像提供。 |
| SD 安装负载 | `theme.ini`、`theme.tmb`、`assets.index`、`*.bin` | 是 | 用户可替换主题的运行时格式。 |

`.tmt` 的归档布局固定为：

```text
<id>-<version>-<target-profile-id>.tmt  (ZIP)
├── package.ini
├── DESCRIPTION.txt
├── README.md
├── signature/manifest.sha256
├── signature/release.ed25519.sig         # 受保护发布 CI 生成
└── payload/
    └── themes/
        └── <theme-id>/
            ├── theme.ini
            ├── theme.tmb
            ├── assets.index
            ├── assets/
            │   └── <asset-id>.bin
            └── fonts/
                └── <font-id>.bin        # 可选
```

运行时不能把 `.tmt` 当作可随机访问的资源数据库，也不能从归档解压时立即启用。它必须先进入 SD staging 目录，完成结构、哈希、签名、预算、契约和布局检查，再原子提交为上述安装树。

## 运行时文件协议

### `theme.ini`

这是固件可读的、受限的 UTF-8 `key=value` 清单。示例：

```ini
kind=theme
id=acme.forest
theme_api=1.0
capability_contract=1.0
engine=lvgl-v9
layout_binary=theme.tmb
asset_index=assets.index
fallback_policy=page
default_variant=touch_full
max_layout_nodes=384
max_loaded_asset_bytes=196608
max_single_asset_bytes=24576
requires_color_depth=16
```

固件必须拒绝未知的必需字段、路径越界、ID 不一致、版本不兼容和高于设备上限的预算声明。清单只能指向当前主题目录内、已在归档哈希清单中登记的相对文件。

### `theme.tmb`

`theme.tmb` 是打包工具从主题源编译出的 Trail Mate Theme Binary。其作用是描述：

- 已公开 `token_id` 的颜色、间距、圆角等受限设计令牌；
- `route_id` 到受限布局节点树的映射；
- 固件已公开的 `slot_id` 在布局中的位置；
- `asset_id` 和资源索引条目的引用；
- 主题包的精确 `target_profile_id` 与该 profile 的资源预算。

它不含作者 YAML、任意 JSON、脚本、网络 URL、回调地址、C++ 符号、可执行字节码或业务数据。固件通过 magic、格式版本、长度、索引范围、节点深度、枚举合法性和文件哈希进行失败关闭式校验。

### `assets.index` 与 `assets/*.bin`

`assets.index` 是固定版本的资源索引。每一项至少绑定：

```text
asset_id → 相对 .bin 路径、类型、宽高、色深、压缩/解码估算、SHA-256
```

`assets/*.bin` 是由主机工具转换好的 LVGL 静态图像资源。固件只会根据 `asset_id` 在 `assets.index` 中查询并按需打开对应 `.bin`，不会扫描 FFat/SD 文件夹、更不会加载 SVG/PNG。SD 主题的可选图标失败时使用 FFat `builtin.default` 的对应图标；SD 主题的必需资源缺失或索引坏掉时拒绝该主题或该页面。FFat 默认资源缺失或核心索引坏掉时进入 rescue。

## 主题活动状态双槽的角色

`/trailmate/packs/index/theme-state.a` 与 `theme-state.b` 不是主题作者可提交的文件，而是固件在 SD 上维护的两个固定大小、带 CRC 的二进制事务记录。每条记录包含：

```text
generation、phase（builtin/pending/committed/rollback）、
current theme id/version/archive hash、previous theme id/version/archive hash、
activation transaction id、payload SHA-256、CRC32
```

固件写入时选择较旧或无效的槽位，写满后重新读取并核对 CRC；启动时选择 CRC 正确且 generation 最大的记录。候选主题先以 `pending` 记录，渲染自检通过后再写入 generation 更高的 `committed` 记录。启动发现 `pending`、目标版本目录缺失或校验失败时，恢复 previous；当 previous 不可用时强制取 FFat `builtin.default`。SD 上任何主题文件都无权直接修改这两个记录。

## 固件启动与运行时加载流程

```text
开机
  → 初始化能力壳、UX Pack 和 rescue
  → 挂载 FFat
       └─失败：停留 rescue，显示 FFat 恢复诊断
  → 读取并验证 factory-theme.header、FFat builtin.default 的 manifest/tmb/assets index
       └─失败：停留 rescue，禁止把 SD 主题当作默认主题
  → 以 FFat builtin.default 构建完整当前界面
  → 尝试挂载 SD
       └─失败：维持 FFat builtin.default
  → 读取 index/theme-state.a 与 index/theme-state.b，选择 CRC 正确且 generation 最大的记录
       └─无记录/ID 为 builtin.default：维持 FFat builtin.default
  → 从 index/theme-index.a 与 index/theme-index.b 确认当前 ID/版本/hash 是已验证的 theme-bundle
  → 打开 themes/<id>/versions/<version>-<sha8>/theme.ini
  → 校验 API、能力契约、UX Pack、显示、存储与内存预算
  → 校验 theme.tmb、assets.index、资源哈希和必需槽位
       └─失败：记录诊断，维持 FFat builtin.default
  → 在 UI 帧边界绑定外部主题覆盖层
  → 对目标 profile 的菜单、全部 route、编辑页、确认页和输入路径执行完整自检
       └─失败：恢复 FFat builtin.default 或 previous_theme_id
  → 成功：外部主题生效；业务、路由和动作仍由固件执行
```

运行中若 SD 被移除或资源读取连续失败，固件不得在当前页面等待、崩溃或显示裸空白界面。它应停止依赖外部资源，在安全帧恢复 FFat `builtin.default`，并让 Extensions 显示主题的不可用诊断。运行中若 FFat 默认资源读失败，必须切换 rescue；不能声称仍能可靠显示完整默认主题。

## 由此产生的实现边界

- 当前界面必须先能以 FFat `builtin.default` 通过同一能力契约运行，再允许外部主题覆盖；这是回归基线。
- 外部主题加载器只处理 SD 安装格式，不负责下载 ZIP、业务数据或 UX Pack 选择。
- 包安装器只把经过验证的 payload 原子写到 SD，不负责构造 LVGL 页面。
- Extensions 负责向用户发起安装/启用/恢复，不直接解析主题布局。
- UX Pack 继续决定设备有哪些能力；主题运行时只能为该能力集合选取资源与布局。

用户主题 Flash 缓存、主题热更新、按时间切换主题或跨设备同步主题不属于本协议；如产品要引入任一能力，必须在不破坏 `FFat builtin.default + SD 外部覆盖层 + rescue` 安全模型的前提下另立完整扩展设计，不能改变当前协议的信任和恢复语义。
