# 05：第三方主题开发指南（拟发布版）

## 这份指南适用于谁

本指南面向希望为 Trail Mate 制作“界面主题包”的设计师和开发者。主题包不是业务插件：你可以改变设备界面的视觉、图标和已声明组件的布局，但不能增加功能、删除功能、读取用户数据或运行代码。

在主题 API `1.0` 正式冻结前，本指南中的命令、文件名和示例均属于预览接口。请只在 ESP32 测试设备或官方测试工具中使用预览包，不要承诺其可跨预览固件版本兼容。

## 你可以和不可以做的事

### 可以做

- 为菜单、页面、操作和状态替换官方公开 `asset_id` 对应的图标；
- 定义页面背景、卡片、边框、文字、状态色、圆角、间距、阴影和有限动效的设计令牌；
- 在每个路由允许的容器中，把公开 `slot_id` 排为网格、列表、行、列、栈、标签、滚动区或受控溢出区；
- 为每个声明支持的 ESP32 `target_profile_id` 提供独立的完整主题目录；
- 提供主题的名称、预览图、描述、许可证和无障碍说明。

### 不可以做

- 打包或执行任意代码、脚本、二进制文件、宏、网络请求或安装后命令；
- 创建自己的菜单入口、业务路由、设置项、后台任务、协议、权限或硬件访问；
- 删除、不可达化、伪装或重定义固件的必要操作，例如返回、发送、确认、取消、保存和危险操作确认；
- 读取或处理聊天消息、联系人、Wi-Fi 密码、密钥、定位原始数据、SD 文件路径或其他业务数据；
- 将自己的文案作为固件菜单/动作的唯一可见标签。主题应优先使用固件本地化文本；自定义文案只用于主题名称、作者信息和纯装饰内容；
- 覆盖语言包字体链或以主题字体解决用户输入/聊天文本缺字问题。

## 开始前的准备

你需要：

1. 与目标固件相同主版本的 Theme SDK；
2. 每个声明 target/profile 的 ESP32 测试设备或官方目标测试工具；
3. SVG 或 PNG 格式的原创/有授权图标资源；
4. 已阅读 [界面能力目录与稳定契约](./02-界面能力目录与稳定契约.md)；
5. Trail Mate 仓库的 fork 或可提交分支，以及将主题提交为 Pull Request 的 GitHub 账号；主题发布签名由受保护分支上的官方 CI 完成，作者不提交私钥或已签名归档。

SDK 会导出下列机器可读文件，主题工程只应依赖它们：

```text
sdk/
├── capabilities-1.0.json     # capability_id、route_id、action_id、slot_id
├── assets-1.0.json           # 可覆盖 asset_id 及规格
├── tokens-1.0.json           # 可覆盖 token_id、类型和上下限
├── targets-1.0.json          # ESP32 target/profile、UX Pack、显示、输入与预算
├── schema/theme-source.json  # 作者源格式 Schema
└── samples/                  # 可构建的完整参考主题
```

不要从固件源代码中复制 `lv_image_dsc_t` 名称、硬编码像素坐标，或解析 C++ 文件来获取接口；这些都不是第三方稳定 API。

## 创建工程

第三方主题在仓库中以如下目录提交；不要在 `packs/`、`site/` 或固件资源目录中创建主题源：

```text
themes/community/acme/acme.forest/
├── package.ini                # 主题家族发布元数据
├── DESCRIPTION.md
├── CHANGELOG.md
├── LICENSE.txt
├── theme-source.yaml          # 声明所含的 profile 目录
├── profiles/
│   ├── p4_tft_touch/
│   │   ├── theme.yaml         # 此 profile 的唯一 token、资源映射与布局
│   │   ├── assets-src/
│   │   ├── previews/
│   │   ├── accessibility.yaml
│   │   └── tests/expected-routes.yaml
│   └── p4_amoled_touch/
│       └── ...独立的完整主题源...
└── shared/                    # 只允许许可证、文案或显式复制的原始资产
```

用拟议工具创建骨架：

```powershell
python tools/theme_pack.py init --root themes\community\acme\acme.forest --id acme.forest --name "Forest Field" --api 1.0 --profiles p4_tft_touch,p4_amoled_touch
```

该命令应生成 SDK 当前版本对应的完整参考项目，不应从网络下载未知模板。

## 编写 `package.ini`

请保持主题的发布信息完整：

```ini
kind=package
id=acme.forest
package_type=theme-bundle
version=0.1.0
display_name=Forest Field
summary=低眩光的户外触控主题。
description=DESCRIPTION.txt
readme=README.md
author=Acme Themes
homepage=https://example.invalid/acme-forest
license=CC-BY-4.0
min_firmware_version=0.2.0-alpha
theme_api=1.0
capability_contract=1.0
supported_target_profiles=p4_tft_touch,p4_amoled_touch
coverage=full
tags=theme,outdoor,low-glare
```

准确声明支持范围非常重要。请不要为了在搜索中出现更多设备而填写未经截图和交互测试的 target/profile。Pager、T-Deck、T-Watch、T-Deck Pro mono、Tab5 与 P4 的可用槽位、焦点要求、输入方式与资源预算并不相同。每个已声明 profile 必须完成它的完整 route 集合，未声明 profile 由安装器显示为不兼容。

`package.ini` 是作者源主题家族清单。CI 生成的每个 `.tmt` 会写入唯一的 `target_profile_id`，而不是把这两个 profile 一起装入一个归档。安装器因此不会把 TFT 的坐标、资源或触控规格安装到 AMOLED 设备。具体归档规则见 [主题包格式与固件接口](./03-主题包格式与固件接口.md#theme-source-and-device-archive)。

## 编写 profile 专属 `theme.yaml`

一个完整主题源文件的结构示意如下：

```yaml
api: "1.0"
theme:
  id: acme.forest
  display_name: Forest Field
  target_profile_id: p4_tft_touch

tokens:
  color.page_bg: "#10251D"
  color.surface: "#1C3A2D"
  color.surface_alt: "#294C3A"
  color.text: "#F8F2E6"
  color.text_muted: "#C7D3C3"
  color.accent: "#C9A34A"
  color.error: "#E2675A"
  spacing.s: 6
  spacing.m: 10
  spacing.l: 16
  radius.card: 12

assets:
  app.chat: assets-src/app.chat.svg
  app.map: assets-src/app.map.svg
  app.settings: assets-src/app.settings.svg
  app.extensions: assets-src/app.extensions.svg
  action.back: assets-src/action.back.svg
  action.send: assets-src/action.send.svg
  status.error: assets-src/status.error.svg

layouts:
  shell.dashboard:
    root:
      type: column
      children:
        - slot: shell.status
        - slot: shell.menu.items
          grow: 1
        - slot: shell.notification

  chat.compose:
    root:
      type: column
      gap: token.spacing.m
      children:
        - slot: chat.compose.title
        - slot: chat.compose.editor
          grow: 1
        - type: row
          justify: space_between
          children:
            - slot: chat.compose.cancel
            - slot: chat.compose.send
        - slot: chat.compose.delivery_status
```

字段的可用范围必须由 SDK Schema 决定。比如颜色格式、字号上限、合法容器、节点深度、槽位类型和可选字段都由工具验证；不要假设任意 LVGL 属性都能写入。

## 布局规则

### 必需槽位

每个路由都有必需槽位。完整、可点击的逐路由定义在 [必需槽位清单](./02-界面能力目录与稳定契约.md#required-slot-catalog)，其中 [`chat.compose` 的槽位](./02-界面能力目录与稳定契约.md#chat-compose-required-slots) 明确列出了标题、编辑器、发送、取消和投递状态。它们可以视觉上差异很大，但仍必须：

- 在当前目标的触摸/键盘/编码器输入模式下可达；
- 使用匹配的组件类型；
- 得到固件本地化的可读标签或同等的文本替代；
- 具备焦点提示或满足目标 profile 的触控面积要求；
- 保留业务语义，例如“取消保留草稿”“发送有投递状态”。

工具会在构建前报告缺失、重复、未知或类型不匹配的槽位。此类错误不能通过“忽略警告”发布。

### 可选槽位与紧凑显示

固件会把某些信息声明为可选槽位。你可以把它们放进公开的 `overflow` 容器、缩短为徽章或在小屏隐藏其视觉呈现，但不能让已公布的必需动作随之丢失。必要时为紧凑 UX Pack 单独制作布局变体。

### 不要用文字或颜色单独表达状态

错误、警告、成功、离线、正在加载和危险动作须同时使用形状/图标、颜色与固件文案。不要把“删除”“关机”“应用无线配置”设计为与普通确认相同的无标签小图标。

## 图标与预览资源

- 首选原创 SVG；工具在构建时转为目标设备可加载格式。
- 图标画布、最大像素、色深和透明度以 `assets-1.0.json` 为准。超过上限会被拒绝。
- 每个资源名必须是 SDK 给出的 `asset_id`。未声明的 `asset_id` 即使文件存在也不会打进主题包。
- 必须提供图标的语义标签。对于只有图标的动作，固件会使用本地化动作名称作为无障碍替代文本。
- 预览图不等于运行时资源。请将它置于 `previews/`，不要把大截图放入 `assets-src/` 以免占用设备资源预算。
- 不得提交受版权/商标限制但没有分发授权的图标、字体或截图。

## 构建、检查和本地验收

拟议的完整工作流如下：

```powershell
# 只检查源码、接口和预算；不生成归档
python tools/theme_pack.py validate --source themes\community\acme\acme.forest --sdk themes\sdk\theme-api-1.0 --target p4_tft_touch

# 仅为 P4 TFT 编译布局、转换资源并生成 profile 专属 .tmt
python tools/theme_pack.py build --source themes\community\acme\acme.forest --sdk themes\sdk\theme-api-1.0 --target p4_tft_touch --out dist

# 解读生成物，确认归档中只有允许文件且哈希可复算
python tools/theme_pack.py inspect --package dist/acme.forest-0.1.0-p4_tft_touch.tmt

# 对声明的每个 target/profile 渲染完整 route 集合，检查截图、焦点和动作可达性
python tools/theme_pack.py test --package dist/acme.forest-0.1.0-p4_tft_touch.tmt --target p4_tft_touch
python tools/theme_pack.py build --source themes\community\acme\acme.forest --sdk themes\sdk\theme-api-1.0 --target p4_amoled_touch --out dist
python tools/theme_pack.py test --package dist/acme.forest-0.1.0-p4_amoled_touch.tmt --target p4_amoled_touch
```

发布前必须验证每个已声明 target/profile 的完整 route 集合，包括仪表盘、聊天编辑、设置编辑、扩展安装确认、地图、错误/离线状态、危险操作确认、输入、全局返回，以及该 profile 特有的 mono/蜂窝/表盘/唤醒页面。只有菜单截图漂亮不代表主题合格。

## 版本与兼容性

请在以下场景更新版本：

| 变化 | 建议版本递增 |
| --- | --- |
| 图标修复、颜色/间距小改、描述修订 | patch，例如 `1.0.0 → 1.0.1` |
| 新增目标、增补页面布局、较大视觉改版 | minor，例如 `1.0.0 → 1.1.0` |
| 移除支持目标、提高主题 API/能力契约要求、破坏旧布局 | major，例如 `1.x → 2.0.0` |

无论改动大小，只要 `.tmt` 归档内容变化，就必须更新版本和归档 SHA-256。不要覆盖一个已经发布的同名版本。

## 以 Pull Request 发布主题

Trail Mate 不接受第三方直接上传为设备目录或 Release 的主题归档。请将可审查的主题源提交到 `themes/community/<publisher-id>/<theme-id>/`，并创建 Pull Request。完整权限边界和 CI 发布流程见 [主题 PR、CI 与 GitHub Pages 发布协议](./15-主题PR、CI与GitHubPages发布协议.md)。

1. 作者提交 `package.ini`、每个 profile 的 `theme.yaml`、资源源文件、许可证、说明、预览源和测试期望；不要提交 `.tmt`、签名、FFat 映像或 Pages 生成文件。
2. 无机密 PR CI 针对每个声明 profile 重新执行验证、确定性打包、反向读取、全路由截图和无障碍检查，并把报告作为审阅工件。
3. 主题维护者审核稳定能力契约覆盖、资源版权、页面语义和可访问性；安全维护者审核主题 SDK、策略或工作流变动。
4. 合并至受保护分支后，受信任 CI 从冻结提交构建 profile 专属 `.tmt`、签名 TMCP 目录、Release 附件和 GitHub Pages 详情页。签名私钥不属于作者源、归档或 PR CI。

用户可以将 Release/Pages 中由 CI 发布的同一已签名 `.tmt` 复制到 SD 后安装；设备照样校验目录摘要、包签名、格式、哈希、预算、精确 profile 与布局。作者本地生成的未发布归档不属于设备可安装的公开主题，不能借由 SD 绕过 PR、审核、CI 发布或主题无代码边界。

## 提交前自检清单

- [ ] `package.ini` 中类型为 `theme-bundle`，ID、版本、API 和支持目标准确。
- [ ] 不含脚本、二进制、网络 URL、嵌套归档、符号链接或未索引文件。
- [ ] 所有使用的 `asset_id`、`token_id`、`route_id` 和 `slot_id` 都来自 SDK。
- [ ] 每个声明 target/profile 的完整 route、必需槽位、输入路径和确认路径都通过验证。
- [ ] 每个必需动作可达，返回、取消、保存、发送和危险确认不被削弱。
- [ ] 图标、文字、焦点和触控面积通过无障碍规则。
- [ ] 所有资源、解压后大小和运行时估算 RAM 在目标预算以内。
- [ ] 主题在每个声明 target/profile 的 ESP32 设备或官方目标测试工具上跑过完整流程。
- [ ] 已更新版本、变更说明和许可证；PR 中未包含 `.tmt`、签名、FFat 映像、密钥或 Pages 生成物。
- [ ] 已在 PR 描述中列出声明的 target profile、全路由验证结论、实机/官方目标测试证据和预览变更。

如果你的目标是创建新的业务功能或页面，请不要伪装成主题包。请先与 Trail Mate 维护者讨论独立的能力扩展模型及其权限、安全和审核要求。
