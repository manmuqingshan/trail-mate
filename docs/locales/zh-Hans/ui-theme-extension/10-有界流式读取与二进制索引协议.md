# 10：有界流式读取与二进制索引协议

## 硬规则

主题系统运行在 RAM、堆碎片和任务栈都敏感的嵌入式固件上。因此以下规则是硬约束，不是优化建议：

> **设备端的主题安装、启动、主题列表、主题详情、主题激活、资源查询和主题渲染路径均不得解析 JSON，也不得把不可信主题数据构造成无上限的对象树、`std::string`、`std::vector`、cJSON 节点或递归 AST。**

JSON 可以留在 PC/CI/网站生成阶段，用于作者工程、发布工具和静态网站；进入设备的主题协议必须是固定上限、可流式验证、失败关闭的行式小清单或二进制记录。

## 为什么 JSON 不适合这个路径

JSON 的风险不仅是文件字节数：

- 解析器通常先持有完整输入，再为键、值、数组和对象分配节点；峰值远大于文件本身；
- 描述、标签、目标列表和资源列表的长度容易随着第三方包增长，难以预先限制；
- 反复刷新目录、打开 Extensions 或扫描 SD 会造成堆碎片；
- 递归解析、异常分支和错误 JSON 使栈与错误恢复难以审计；
- 一个主题列表或远程目录被错误地合并为大 `vector` 时，可能让 UI 任务内存峰值与主题数量线性增长。

即使当前已有其他扩展类型使用 JSON，也不应让新主题系统把这一实现选择扩大到资源更多、第三方更多、需要启动回退的主题路径。

## 设备端三类读取器

| 读取器 | 输入 | 输出 | 内存模型 |
| --- | --- | --- | --- |
| `ThemeManifestReader` | 单个 `package.ini` / `theme.ini` | 固定大小 `ThemeManifest` | 单行缓冲 + 固定字段数组；总文件与单行均有限制。 |
| `ThemeIndexReader` | `theme-index.a/b`、`theme-state.a/b` | 一个固定记录或一个状态记录 | 读取固定头和固定记录；不把整个索引复制到堆。 |
| `ThemeCatalogReader` | HTTP/SD 的 `ThemeCatalogPage` | 当前页的固定数量 `ThemeCatalogRecord` | 页头后顺序读取，最多保留一页；不累计所有页。 |
| `ThemeBinaryReader` | `theme.tmb`、`assets.index` | 当前路由/资产的有界描述 | 先验证头和偏移；按需读取固定记录或当前页面节点块。 |

这些读取器的输出结构必须是固定容量 POD 或等价的有界结构。来自存储/网络的字符串采用 `uint8_t length + char bytes[N]` 或固定 NUL 终止字节数组，读取时验证 UTF-8 和最大长度；不得以文件内容长度构造动态字符串。

## 小型文本清单：`theme.ini` 与 `package.ini`

文本清单仍可采用现有易维护的 `key=value`，因为它们只包含很少的核心字段，但必须满足：

| 限制 | 必须冻结的 profile 值 | 规则 |
| --- | ---: | --- |
| `package.ini` 最大字节 | 4 KiB | 超限立即拒绝，不尝试截断后继续。 |
| `theme.ini` 最大字节 | 2 KiB | 同上。 |
| 单行最大字节 | 192 B | 使用固定行缓冲；超限即拒绝该包。 |
| 最大键数 | 40 | 只接受白名单键；重复的单值键拒绝。 |
| ID 最大长度 | 47 B ASCII | 只接受规范主题 ID 字符集。 |
| 版本最大长度 | 23 B ASCII | 只接受严格 SemVer。 |
| 显示名称最大长度 | 63 B UTF-8 | 在字符边界截断前由工具拒绝超限。 |
| 摘要最大长度 | 95 B UTF-8 | 仅用于当前页列表/详情摘要。 |

读取算法固定为：以 192 B 缓冲逐行读取 → 拒绝无换行的超长行 → 查白名单键 → 将值复制入对应定长字段 → 完成后检查必填字段与字段关系。它不保存原始全文，也不构建键值 map。

## 已安装主题索引：`theme-index.a/b`

### 为什么不使用 `installed.json`

主题运行时必须在启动早期、SD 异常和外部输入不可信时仍保持常数级内存。通用 JSON 索引会迫使它解析全部包记录，且主题数量增长会直接扩大内存风险。因此主题单独维护有容量上限的快照索引；原有 `installed.json` 可以保留给当前非主题包兼容路径，但不能成为 Theme Runtime 的依赖。

### 文件布局

```text
/trailmate/packs/index/
├── theme-index.a
├── theme-index.b
├── theme-state.a
└── theme-state.b
```

`theme-index.a/b` 是同一个索引的双槽快照。每个文件由固定大小头部和固定数量的记录槽组成；未使用槽全零。最大记录数在固件编译时确定，不因 SD 内容增大。

主题索引容量按每个 ESP32 target/profile 冻结，不能用一个泛化档位覆盖全部设备：

| profile | 最大已安装主题版本记录 | 主题索引最大字节 |
| --- | ---: | ---: |
| `pager_compact_sx1262` | 8 | ≤ 4 KiB |
| `pager_compact_lr1121` | 8 | ≤ 4 KiB |
| `tdeck_full` | 8 | ≤ 4 KiB |
| `twatch_compact` | 8 | ≤ 4 KiB |
| `tdeck_pro_240x320_a7682e` | 8 | ≤ 4 KiB |
| `tdeck_pro_240x320_pcm512a` | 8 | ≤ 4 KiB |
| `tab5_touch` | 16 | ≤ 8 KiB |
| `p4_tft_touch` | 16 | ≤ 8 KiB |
| `p4_amoled_touch` | 16 | ≤ 8 KiB |

这里统计的是“版本记录”，不是主题 ID；一个已激活主题和它保留的上一个版本占两条记录。空间不足时拒绝安装或要求用户卸载非活动主题，不能扩大记录数组。

### 索引头部

```text
magic                 4 bytes = TMIX
format_major          u16
format_minor          u16
record_bytes          u16
capacity              u16
record_count          u16
reserved              u16 = 0
generation            u64
payload_crc32         u32
header_crc32          u32
```

加载器检查 magic、主版本、记录大小、capacity 是否等于本固件支持值、`record_count <= capacity`、文件总长度、两个 CRC 和 generation。任一检查失败，该槽无效；两个槽都无效时不扫描目录，而是将外部主题视为不可用并使用 FFat `builtin.default`。FFat 默认主题不可用时，由上层进入 rescue。

### 索引记录

记录应固定为 384 B 或更小，并至少包括：

| 字段 | 最大容量/编码 | 说明 |
| --- | --- | --- |
| 主题 ID | 长度 + 最多 47 B ASCII | 同时用于规范路径推导。 |
| 版本 | 长度 + 最多 23 B ASCII | 严格 SemVer。 |
| 归档 SHA-256 | 32 B 原始字节 | 不保存 64 字符十六进制字符串。 |
| 安装时间/安装代数 | `u64` / `u32` | 用于排序和诊断。 |
| `theme_api` | `u16 major` + `u16 minor` | 兼容性检查。 |
| 契约哈希 | 32 B 原始字节 | 与固件 SDK 契约直接比对。 |
| 精确 target profile | 固定 profile 枚举值或 16 B 定长 ID | 一条记录只对应一个设备 profile，不存“可能兼容”的可变数组。 |
| 验证/安装标志 | `u32` 位图 | `verified`、`inactive`、`quarantined` 等。 |
| 已安装字节 | `u32` | 预检/空间诊断。 |
| 显示名称 | 长度 + 最多 63 B UTF-8 | Extensions 列表所需的唯一用户文本。 |
| 记录 CRC | `u32` | 防止单记录损坏。 |

`summary`、长描述、标签、主页 URL、预览资源和作者的完整说明不常驻索引；它们只在用户进入单个详情页时按需、限长读取。索引加载时可逐记录扫描，找到当前主题或填充当前可见的最多 N 条列表项后停止，不需要读完整数组。

## 活动状态：`theme-state.a/b`

活动状态同样使用固定记录双槽，而不是 JSON。它只保存启动恢复所需的固定字段：

```text
current:  id[47] + version[23] + target_profile_id[32] + archive_sha256[32]
previous: id[47] + version[23] + target_profile_id[32] + archive_sha256[32]
generation, transaction_id, phase, failure_count, payload_sha256, CRC32
```

写入逻辑是：选择较旧/无效槽 → 写完整 record → 刷新 → 读回并验 CRC → 将新 generation 作为有效状态。启动时选择 generation 最大的有效槽。不存在有效记录的默认含义固定为 FFat `builtin.default`；FFat 失效则由上层进入 rescue。

## 远程主题目录：分页 `ThemeCatalogPage`

### 为什么目录也不能是 JSON

设备不应下载 `packs.json` 后解析全量目录，即使只为了显示主题。第三方主题数量增长后，这会成为下载时间、RAM 与堆碎片的共同瓶颈。主题目录必须成为独立的、按目标过滤、分页的二进制端点。

建议 URL 语义（具体路径可在发布系统冻结时调整）：

```text
GET /api/theme-catalog/v1?page_size=12&cursor=<opaque>&target_profile_id=<id>
Accept: application/vnd.trailmate.theme-catalog+binary
```

响应是一个 `TMCP`（Trail Mate Catalog Page）二进制页：

```text
header:
  magic, version, page_generation, record_bytes, record_count (≤ 12),
  next_cursor[16], payload_crc32, catalog_key_id, signature
records:
  fixed ThemeCatalogRecord × record_count
```

`ThemeCatalogRecord` 仅包含列表/预检所需的定长数据：ID、版本、精确 `target_profile_id`、短显示名称、短摘要、归档大小、归档 SHA-256、主题 API、契约哈希、内存档位位图、发布 key ID、发布标志和由可信 base URL 推导的下载键。它不携带不受限 URL、长描述、任意标签数组或资源列表。

客户端读取页头后立刻验证长度、record count、CRC 和目录签名，再逐条读入一个固定 `ThemeCatalogRecord` 缓冲，填充当前最多 12 行列表。用户翻页才释放当前页并请求下一 cursor。不能累积“所有已看过的页”。

### 详情与预览

- 列表只显示索引中的短名称和短摘要；
- 用户选中某条时才请求一个同样限长、签名的详情记录，或在已下载的包内流式读取 `DESCRIPTION.txt`；
- 长描述最大 1 KiB，按行/块显示，不构造整页字符串；
- 预览图是受尺寸限制的独立二进制资源，按需读取且不与运行时图标缓存混用。

## `theme.tmb`：验证与按页读取

主题二进制不能因为“格式是二进制”就一次读入内存。加载过程分为三层：

1. **头部验证**：读取固定 80 B 头部，检查 magic、主版本、总长度、CRC、契约哈希和各表 offset；不分配大对象。
2. **目录验证**：逐条读取固定大小的 route/asset 引用目录，检查数量和范围；每个 ESP32 profile 的硬上限必须不低于该 profile 的完整 `CapabilityRegistry` route 数，并由 SDK 与固件共用同一个生成值。主题不能用省略未声明 route 的方式通过验证。
3. **按页加载**：用户打开路由时，只读取该路由的布局节点块到固定工作缓冲。工作缓冲大小、节点数和字符串表上限由 target profile 的预算表给出；验证通过后立即构建该页，退出页面释放或复用该工作缓冲。

主题激活可预读头部和路由目录，但不能把所有页面节点、原始字符串表或所有资产元数据展开到堆。SD 主题错误页立即回退 FFat `builtin.default` 的该路由；FFat 路由错误则进入 rescue。

## `assets.index` 与资源读取

`assets.index` 使用固定长排序记录；记录键为 SDK 分配的 `asset_id` 整数，不是可变字符串。读取一个图标时：

```text
asset_id
  → 在索引中按记录数上限做二分/有界顺序查询
  → 读一条固定 AssetRecord
  → 验证相对路径、尺寸、SHA-256 和当前主题 generation
  → 用固定大小 I/O 块流式读取 .bin
  → 放入受限 LRU/固定槽缓存，或退回 FFat builtin.default 资源
```

资源记录数由每个 ESP32 target profile 的固定预算给出，且必须覆盖该 profile 的 FFat 默认资源与主题完整 route 所需资源；索引记录最大 96 B。图像读取缓冲属于平台/主题运行时的固定工作区，不能以文件大小在栈或堆上动态分配。

## C++ 实现禁止项

对所有由 SD、网络或主题包提供的数据，以下做法禁止进入 Theme Runtime：

```cpp
// 禁止示例：不可信输入驱动的无界对象/容器。
std::string whole_file = read_entire_file(path);
auto root = cJSON_Parse(whole_file.c_str());
std::vector<ThemeRecord> all_records;
while (...) all_records.push_back(parse_record(...));

// 禁止示例：按不可信长度在任务栈上分配。
uint8_t bytes[untrusted_length];
```

允许的模式应类似：固定 I/O 块、固定记录、固定页缓存、带长度检查的 `std::array`/静态数组或长期拥有的成员工作区；每一次来自存储的长度都在复制、解析、寻址、乘法和分配之前检查上限。

## 验收与故障注入

在实现主题加载器前，必须用真实 SD 和模拟网络流验证：

1. 目录页有 12 条、1 条、0 条、截断、错误 CRC、错误签名、未知记录大小时，最大堆/栈保持常数；
2. 主题索引满、单记录 CRC 坏、两个索引槽都坏、state `pending` 时，FFat 正常的设备仍启动 `builtin.default`；FFat 不正常时进入 rescue；
3. 主题清单超 2/4 KiB、单行超 192 B、UTF-8 非法、重复字段、未知必填字段时被拒绝；
4. `theme.tmb` 声称巨大表、偏移溢出、循环节点、过深树或页面块超上限时被拒绝；
5. 反复翻页、打开详情、预览、激活、拔卡后，主题路径没有随主题数量增长的堆占用或碎片；
6. 静态检查证明 Theme Runtime 没有 cJSON、JSON DOM、`read_entire_file`、不受限 `std::string`/`vector` 或变长栈数组。

只有这些证据通过，主题的“扩展中心可以下载/安装主题”才是嵌入式可持续的设计，而不是将桌面端的对象模型搬到 ESP 上。
