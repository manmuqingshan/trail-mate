# 03：主题包格式与固件接口

## 设计选择

建议把主题作为现有扩展体系中的新包类型：`package_type=theme-bundle`。分发文件扩展名使用 `.tmt`（Trail Mate Theme），其物理格式为 ZIP；安装后只将受允许的 `payload/themes/<theme-id>/` 解压至主题根目录。一个 `.tmt` 是一个精确 `target_profile_id` 的设备包，不是包含多台设备资源的通用归档。

主题作者编辑可读的 YAML/JSON 源文件，但固件**不解析作者的 YAML/JSON**。主机工具把它编译为固定版本、长度受限、可流式读取的 `theme.tmb`（Trail Mate Theme Binary）和 LVGL 可加载的资源。固件只读取 SD 已安装主题目录中的 `theme.ini`、资源索引和已校验的二进制文件；它不会从 ZIP 中直接渲染，也不会从作者源文件加载。

这项二阶段格式避免在 ESP 端引入宽松通用解释器，也让确定性校验、内存预算和未来 ABI 兼容更容易控制。

## 包类型与安装位置

| 层级 | 名称/路径 | 作用 |
| --- | --- | --- |
| 作者工程 | `my-theme/` | 可读源、PNG/SVG、布局 YAML、元数据、预览图。 |
| 出厂默认主题 | FFat `/trailmate/factory/themes/builtin.default/` | 固件配套的完整默认图标、令牌、布局和索引；由 FFat 镜像写入。 |
| 分发归档 | `<theme-id>-<version>-<target-profile-id>.tmt` | 一个精确 profile 的 ZIP 容器，供目录、侧载或下载使用。 |
| 归档负载 | `payload/themes/<theme-id>/` | 唯一允许被安装到设备的主题负载。 |
| 设备安装路径 | `/trailmate/packs/themes/<theme-id>/` | 外部主题的唯一安装位置：SD 卡。`<theme-id>` 为规范化主题 ID。 |
| 已安装主题索引 | `/trailmate/packs/index/theme-index.a` 与 `theme-index.b` | 固定容量、带 CRC 的主题安装索引双槽；Theme Runtime 不读取 JSON。 |
| 当前激活记录 | `/trailmate/packs/index/theme-state.a` 与 `theme-state.b` | 固定大小、带 CRC 的双槽状态记录；保存当前/上一次主题和激活事务状态，不可由主题包携带。 |

本协议采用“FFat 出厂默认主题 + SD 用户主题”的双层存储。用户下载的 `theme-bundle` 不自动写入 FFat，而是只写入 SD。FFat 中仅保留随固件版本发布、受 `FactoryThemeHeader` 验证的 `builtin.default`，不能被 Extensions 覆盖。用户主题的 Flash 缓存不属于本协议；如产品需要该能力，必须在新增协议中完整定义分区预算、磨损策略、信任边界、掉电恢复和卸载语义，不能默认为当前格式的一部分。

设备有两条明确的主题根：FFat 的固定出厂根 `/trailmate/factory/themes/builtin.default/`，以及 SD 的可变用户根 `/trailmate/packs/themes/`。如果 SD 不存在、未挂载、只读、容量不足或在加载中移除，外部主题不得启用，固件使用 FFat 的 `builtin.default`；不得把用户主题悄悄改写为 FFat 安装。FFat 自身不可用时，进入固件 `rescue`，其详细协议见 `11`。

## 归档目录

```text
acme.forest-1.2.0-p4_tft_touch.tmt
├── package.ini                         # 扩展中心的通用包元数据
├── DESCRIPTION.txt                     # 用户可读长描述
├── README.md                           # 主题作者/高级用户说明
├── LICENSE.txt                         # 可选许可证
├── signature/
│   ├── manifest.sha256                 # 归档内文件哈希清单
│   └── release.ed25519.sig             # 受保护发布 CI 生成的包签名
└── payload/
    └── themes/
        └── acme.forest/
            ├── theme.ini               # 运行时主题清单
            ├── theme.tmb               # 由工具编译、固件读取的布局/令牌二进制
            ├── assets.index            # 已编译资源索引，含尺寸、哈希和 asset_id
            ├── assets/
            │   ├── app.chat.bin
            │   ├── app.map.bin
            │   ├── action.send.bin
            │   └── ...
            ├── fonts/                  # 可选；仅限主题 API 允许的渲染字体
            │   └── display-16.bin
            └── preview/
                └── cover.bin           # 可选，扩展中心预览；有独立尺寸上限
```

归档中不能出现以下内容：可执行文件、脚本、动态库、源代码生成缓存、嵌套 ZIP、符号链接、绝对路径、`..` 路径、未在 `assets.index` 声明的资源、密钥、网络配置或任意平台配置文件。

## 固件实际加载的文件格式

安装后的 SD 目录是固件的唯一外部主题输入。固件加载器按以下格式读取，且每种文件职责固定：

| 文件 | 格式 | 是否由固件解析 | 作用 |
| --- | --- | --- | --- |
| `theme.ini` | 小型 UTF-8 `key=value` 清单 | 是 | 提供主题 ID、API、契约版本、二进制路径、资源索引路径和预算声明。 |
| `theme.tmb` | 受版本约束的二进制布局文件 | 是 | 保存预编译令牌、路由布局树、槽位和资源索引引用；不含 YAML/JSON/脚本。 |
| `assets.index` | 受版本约束的二进制或严格行式索引 | 是 | 将 `asset_id` 映射到相对资源文件、尺寸、格式、预算和 SHA-256。 |
| `assets/*.bin` | 固件指定的 LVGL 静态图像二进制 | 是，按需流式读取 | 主题图标/装饰资源；文件必须在索引登记且哈希匹配。 |
| `fonts/*.bin` | 可选、主题 API 明确允许的受限展示字体 | 是，按需加载 | 只能用于授权的展示区域，不替代 locale/font pack。 |
| `package.ini`、`DESCRIPTION.txt`、`README.md` | UTF-8 文本 | 仅 Extensions/诊断读取 | 安装后用于包身份和用户说明，不参与页面布局渲染。 |

固件**不会**加载作者工程中的 `theme.yaml`、SVG、PNG、截图或源代码；这些只是主机工具输入，不能出现在 `payload/themes/<theme-id>/`。固件同样不会扫描 SD 中的任意子目录来“猜测主题”，只能依据经过验证的 `theme-index.a` / `theme-index.b` 与 `theme-state.a` / `theme-state.b` 指向目标版本目录。

## 作者源与设备归档：两个 `package.ini` 的适用范围

主题作者源根中的 `package.ini` 可以说明一个主题家族支持哪些 target profile，并和 `theme-source.yaml` 共同列出各 profile 源目录。CI 以其中一个 profile 为输入时，生成一个独立 `.tmt`；归档根中的 `package.ini` 必须将该多值声明归约为唯一 `target_profile_id`。ESP32 安装器只接受这一种归档清单，绝不从单包中挑选其他设备布局。

```text
作者源：themes/community/<publisher>/<theme>/package.ini
  supported_target_profiles=tab5_touch,p4_tft_touch,p4_amoled_touch

CI 输出：acme.forest-1.2.0-p4_tft_touch.tmt/package.ini
  target_profile_id=p4_tft_touch
  source_theme_id=acme.forest
```

下方示例为**作者源清单**，用于说明主题家族的元数据：

`package.ini` 与现有 locale/content/input bundle 的清单模型保持一致，但主题必须明确类型：

```ini
kind=package
id=acme.forest
package_type=theme-bundle
version=1.2.0
display_name=Forest Field
summary=适用于触控全功能设备的低眩光户外主题。
description=DESCRIPTION.txt
readme=README.md
author=Acme Themes
homepage=https://example.invalid/acme-forest
license=CC-BY-4.0
min_firmware_version=0.2.0-alpha
theme_api=1.0
capability_contract=1.0
supported_target_profiles=tab5_touch,p4_tft_touch,p4_amoled_touch
supported_ux_packs=compatibility,t_display_p4_touch
supported_display_classes=480x320-rgb565,1024x600-rgb565
coverage=full
tags=theme,outdoor,low-glare
```

| 字段 | 要求 | 说明 |
| --- | --- | --- |
| `id` | 必填；全局稳定、小写点分 ID | 安装目录、索引和激活记录的键。不能在不同作者间重用。 |
| `package_type` | 必须为 `theme-bundle` | 使扩展中心、安装器和主题注册表采用主题规则。 |
| `version` | 必填，SemVer | 归档内容、资源、布局或兼容性变化都必须递增。 |
| `min_firmware_version` | 必填 | 低版本不能正确理解字段或二进制格式时必须提高。 |
| `theme_api` | 必填 | 主题格式 API 版本；固件按其做主版本兼容判断。 |
| `capability_contract` | 必填 | 主题依赖的能力/槽位契约版本。 |
| `supported_target_profiles` | 至少一个 | 主题经过验证的 ESP32 target/layout profile ID；不能以“全部”代替。 |
| `supported_ux_packs` | 与 profile 数量相同 | 每个 target profile 对应的固件 UX Pack ID；用于安装时交叉校验。 |
| `supported_display_classes` | 至少一个 | 显示尺寸、色深和方向的逻辑类别，避免误启用。 |
| `coverage` | 必填，值为 `full` | 对每个声明 target profile 覆盖其完整 route 集合；缺页主题不得作为 UI Theme Bundle 启用。 |
| 作者/主页/许可证 | 发布目录必填 | 供用户识别来源与法律信息；不参与运行时能力。 |

`package.ini` 不能声明路由、动作、权限、后台服务、网络地址、安装脚本或目标板名。

CI 生成的归档 `package.ini` 除共同身份字段外，必须具有下列单 profile 字段，并且不携带 `supported_target_profiles`、`supported_ux_packs` 或 `supported_display_classes` 这类多值家族声明：

```ini
kind=package
id=acme.forest
source_theme_id=acme.forest
version=1.2.0
package_type=theme-bundle
target_profile_id=p4_tft_touch
theme_api=1.0
capability_contract=1.0
contract_sha256=<64-hex>
archive_sha256=<64-hex>
coverage=full
```

安装器使用 `target_profile_id` 与启动时解析得到的 `Esp32TargetThemeProfile` 精确匹配。profile 不同即拒绝下载后的安装事务，不能根据相近屏幕尺寸缩放或猜测兼容性。主题源、目标专用归档和 Pages 聚合目录的对应关系见 [第 14 篇](./14-工程目录与独立默认主题规划.md#theme-source-builds-profile-archive)。

## `theme.ini`：运行时主题清单

```ini
kind=theme
id=acme.forest
target_profile_id=p4_tft_touch
theme_api=1.0
capability_contract=1.0
engine=lvgl-v9
layout_binary=theme.tmb
asset_index=assets.index
fallback_policy=page
default_variant=touch_full
variants=touch_full,landscape_keyboard
max_layout_nodes=384
max_loaded_asset_bytes=196608
max_single_asset_bytes=24576
requires_color_depth=16
```

主题清单只描述固件如何读取已编译文件与资源预算；所有作者可读的辅助信息放在归档根目录，避免在运行时反复解析长文本。

| 字段 | 固件校验 |
| --- | --- |
| `kind`、`id`、`target_profile_id` | 必须与 `package.ini` 一致，且 `target_profile_id` 必须等于设备启动时解析的精确 profile。 |
| `theme_api`、`capability_contract` | 必须在固件支持范围内；主版本不兼容即拒绝。 |
| `engine` | 必须与构建目标匹配；只接受本协议明确列出的 LVGL 引擎版本。 |
| `layout_binary`、`asset_index` | 必须是相对、规范化、已列入哈希清单的路径。 |
| `max_*` | 必须不超过该设备和固件编译时的硬上限。主题不能借此提高预算。 |
| `fallback_policy` | 固定只允许 `page`：单页无效则退到内置页。 |

## 主题源模型与 `theme.tmb`

作者使用 `theme.yaml` 描述设计令牌、资源映射和布局模板。它不直接进入归档；工具将它规范化并编译为 `theme.tmb`。

示例源片段：

```yaml
api: "1.0"
tokens:
  color.page_bg: "#10251D"
  color.surface: "#1C3A2D"
  color.accent: "#C9A34A"
  spacing.m: 10
  radius.card: 12
assets:
  app.chat: assets-src/chat.svg
  action.send: assets-src/send.svg
layouts:
  chat.compose:
    root:
      type: column
      children:
        - slot: chat.compose.title
        - slot: chat.compose.editor
          grow: 1
        - type: row
          children:
            - slot: chat.compose.cancel
            - slot: chat.compose.send
        - slot: chat.compose.delivery_status
```

工具会把它变成只包含下列对象的二进制记录：

- 固定 token ID 到合法值的映射；
- 固定 `asset_id` 到资源索引号的映射；
- `route_id` 到布局树的映射；
- 有限类型的布局节点：`row`、`column`、`grid`、`stack`、`overlay`、`scroll`、`tabs`、`slot`、`overflow`；
- 无执行语义的属性：对齐、间距、增长、尺寸区间、可见性档位、样式类和顺序。

`theme.tmb` 禁止包含任意表达式、条件语言、模板插值、回调地址、字符串拼接、资源 URL、文件路径、脚本或用户数据选择规则。可见性只能由固件对可选槽位附带的 `availability` 决定；主题不能自定义“若某能力可用则隐藏另一个能力”的规则。

## 布局语义与强制验证

布局不是随意的 LVGL 对象快照，而是受控的“语义槽位排版”。每个 `route_id` 都有固件提供的 `RouteDescriptor`。

```text
RouteDescriptor
  required_slots: 主题必须放置，且在当前输入模式可达
  optional_slots: 可在紧凑容器中折叠
  allowed_containers: 当前路由允许使用的容器类型
  action_ownership: 每个动作只能由匹配槽位承载
  accessibility: 焦点/替代文本/触控面积/危险确认规则
```

构建工具和固件加载器都需验证：

1. 所有 `required_slots` 恰好出现一次；
2. 未知或弃用 `slot_id`、`asset_id`、`token_id` 被拒绝；
3. 槽位类型相容，例如文本编辑器不能渲染为静态装饰；
4. 每一个可用的必要动作在输入模式中可达；
5. 主要/次要/危险动作的语义不可互换，确认动作不能指向取消动作；
6. 节点数、树深度、字符串大小和整数范围在预算内；
7. 页面可读字号、目标 profile 规定的触控区域、对比度和焦点可见性满足设备要求；
8. 对每个声明 target profile 的完整 route 集合均提供布局；存在未提供的 route、必需 slot 或输入/确认路径时拒绝安装或拒绝启用。

## 资源接口

### 稳定资源键

主题通过稳定 `asset_id` 覆盖资源，例如：

```text
app.chat                 app.map                 app.settings
app.extensions           app.walkie_talkie       app.tracker
action.back              action.confirm          action.cancel
action.send              action.install          action.update
status.success           status.warning          status.error
status.offline           status.loading          shell.logo
```

实际清单由主题 SDK 版本化导出。作者不能声明同名资源来改变固件业务数据，也不能按 C/C++ 变量、`lv_image_dsc_t` 地址或源文件名绑定。

### 格式与预算

- 作者可提交 SVG/PNG 作为**工具输入**；产物必须转换为固件指定的 LVGL 二进制图像格式。
- 每个资产记录 `asset_id`、像素宽高、色深、文件字节数、解码后估算 RAM、SHA-256 和用途。
- 主题格式只接受静态图标和静态装饰图；不接受视频、GIF、网络图像和任意动画脚本。
- 图标必须保留透明背景或在相应 token 背景下可读；状态图标须提供足够的形状区分，不能只依赖颜色。
- 自定义字体仅用于主题允许的展示层，不取代 locale/font pack 的文字覆盖链，也不能造成用户内容缺字。主题字体与语言字体是两类资源，必须分别计入预算。

## 目录与索引接口的扩展

主题不能直接复用“把完整远程目录或已安装列表解析为 JSON 对象树”的模型。设备端主题系统使用独立、有界的二进制协议：

- 已安装主题：`/trailmate/packs/index/theme-index.a` 与 `theme-index.b`；
- 当前/上一次活动主题：`theme-state.a` 与 `theme-state.b`；
- 远程主题发现：按页下载的 `ThemeCatalogPage` 二进制记录流；
- 包详情：在用户选中单个主题时，流式读取受限长度的 `package.ini` / `DESCRIPTION.txt`，不预读全部说明。

每个主题索引记录仍携带以下逻辑字段：ID、版本、精确 `target_profile_id`、归档 SHA-256、SD 存储位置、安装时间、主题 API、能力契约、验证状态和短显示名称。字段在二进制固定记录中以最大长度的字节数组表示，而不是运行时 JSON 字符串或动态容器。完整记录、页大小、字符串上限和 CRC 规则见 [有界流式读取与二进制索引协议](./10-有界流式读取与二进制索引协议.md)。

现有 `installed.json` 可以继续由现有 locale/content/input 包仓库使用，但 Theme Runtime 不读取它，也不以其正确性作为主题启动前提；主题安装成功时由主题专用索引事务写入 `theme-index.a/b`。Extensions 若要同时展示旧包与主题，应为主题调用独立的流式 reader，不应把两类记录合并进一个大对象列表。

“已安装”与“已启用”必须严格区分：设备可安装多个主题版本，但同时只能有一个当前启用主题；内置主题不依赖外部存储，也不写为可卸载包。

## 兼容性规则

加载器应按顺序检查：

```text
归档/签名可信
  → package.ini 与 theme.ini 结构正确
  → 包 ID/版本/哈希一致
  → 固件版本与 theme_api 兼容
  → capability_contract 兼容
  → 当前 target_profile_id 精确匹配
  → 内存/存储/图像预算通过
  → theme.tmb 结构与每页必需槽位通过
  → 资源可读取且哈希匹配
  → 可激活
```

如果主题使用比固件更新的契约，不允许“尽量加载”。这类静默降级会造成用户动作丢失；必须拒绝或走内置主题。

## 版本策略

- `theme_api` 主版本变更：二进制格式或主题表达能力不兼容；旧固件拒绝加载。
- `capability_contract` 主版本变更：已有槽位/动作语义不兼容；主题需要重新构建。
- 主题 `version` 补丁：图标、颜色、小的布局调整、描述修正。
- 主题 `version` 次版本：新增兼容目标、增补路由布局、重要视觉改版。
- 主题 `version` 主版本：删除支持目标、需求显著升级、迁移到不兼容主题 API。
