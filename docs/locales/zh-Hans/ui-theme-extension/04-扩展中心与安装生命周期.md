# 04：扩展中心与安装生命周期

## 目标体验

用户无需了解固件内部目录，即可在 `Extensions` 中发现主题、判断是否适配自己的设备、下载安装、预览、启用、更新或恢复内置主题。出现断电、下载失败、校验失败、资源不足或渲染错误时，设备必须保留一个可启动、可操作的内置界面。

这里的“内置界面”不是抽象的兜底页，而是当前固件已经拥有的完整界面，设计 ID 为 `builtin.default`。它的完整主题资源位于 FFat 出厂镜像内，而非应用固件镜像；外部主题只安装到 SD，不能取代或写入 FFat 出厂资源。FFat 无法使用时，固件进入独立 `rescue` 恢复呈现，展示固定诊断、恢复指引、重启和受控维护入口。

当前扩展页面已具备“包列表 → 包详情 → 安装/卸载确认”和安装进度的基础。本方案只是新增主题分组、激活状态和安全回退，仍复用统一的包目录与安装事务。

主题分组不能沿用“先把所有主题/目录解析到内存列表再渲染”的方式。Extensions 对主题使用最多一页固定数量记录的流式 reader；滚动或翻页时释放上一页，不把远程目录、主题描述或资源元数据留在 UI 堆中。

## 扩展中心信息架构

```text
Extensions
├── 已安装
│   ├── 主题
│   │   ├── 当前主题（启用/恢复内置/详情）
│   │   └── 其他已安装主题（预览/启用/卸载）
│   ├── 语言与字体
│   └── 输入与内容
├── 发现
│   ├── 推荐主题
│   ├── 适配本设备
│   └── 全部包/搜索/标签
└── 下载与诊断
    ├── 安装任务
    ├── 存储与兼容性
    └── 主题恢复/安全模式说明
```

对于没有网络或不支持安装的目标，页面应保留已安装包与内置主题信息，并清楚显示“当前平台不支持在线安装”；不得把不可用操作伪装成可点击按钮。

## 主题包的用户状态

| 状态 | 含义 | 可做操作 |
| --- | --- | --- |
| `remote_available` | 目录有包，设备未安装 | 查看详情、下载/安装。 |
| `incompatible` | 固件、显示、UX Pack、内存或信任条件不满足 | 查看原因；禁止安装/启用。 |
| `downloading` / `verifying` / `installing` | 安装事务进行中 | 查看进度、在安全点取消；不可并发启动同一包。 |
| `installed_inactive` | 已安装但未启用 | 预览、启用、卸载、检查更新。 |
| `installed_active` | 当前生效主题 | 预览、恢复内置、检查更新；不提供直接“删当前主题”。 |
| `update_available` | 目录版本或哈希与已安装索引不同 | 查看变更、更新。 |
| `activation_failed` | 已安装但启动/切换校验失败 | 查看诊断、重试或卸载；保持内置/旧主题。 |
| `quarantined` | 签名、哈希或安全规则失败 | 只能查看诊断/删除；不允许启用。 |

语言包、内容包和输入包继续沿用它们现有的“已安装不等于已加载”规则；主题则遵循“已安装不等于已启用”。不能用一个泛化的 `installed=true` 表达所有生效状态。

## 在线安装事务

建议采用不可中断地保护旧状态的两阶段安装，步骤如下：

```text
1. 目录获取：加载 HTTPS 目录并校验目录签名/可信来源。
2. 预检：比较主题 API、固件版本、精确 `target_profile_id`、内存与可用存储。
3. 用户确认：展示作者、版本、来源、大小、权限声明（应为“无代码”）和兼容性。
4. 下载：写入临时归档；限制重定向、大小、超时和磁盘空间。
5. 完整性：对临时归档计算 SHA-256，比对目录中的预期值。
6. 来源验证：验证受保护发布 CI 的包签名及目录/撤销策略。
7. 解包到 staging：逐项检查路径、文件数、解压后大小、压缩比、哈希和白名单。
8. 主题语义验证：解析清单、检查 theme.tmb、资源索引、预算、必需槽位与目标兼容性。
9. 原子提交：将 staging 原子改名为最终主题目录；更新 installed index。
10. 安装完成：主题处于 installed_inactive，不自动替换用户正在使用的主题。
```

第 9 步之前，已有主题与已安装索引不可被覆盖。任何失败只清除 staging 与下载临时文件，不能破坏正在使用的主题或语言包。

## SD 安装与加载顺序

### 安装目标

对于 `theme-bundle`，下载或本地侧载的 `.tmt` 文件只作为运输容器。安装器完成验证后，只把归档中的：

```text
payload/themes/<theme-id>/...
```

原子解压到 SD：

```text
/trailmate/packs/themes/<theme-id>/...
```

并更新 SD 的：

```text
/trailmate/packs/index/installed.json        # 仅现有非主题包的兼容索引；Theme Runtime 不读取
/trailmate/packs/index/theme-index.a
/trailmate/packs/index/theme-index.b
/trailmate/packs/index/theme-state.a
/trailmate/packs/index/theme-state.b
```

`.tmt` 不作为运行时资源库长期直接读取；是否保留下载归档仅是诊断/缓存策略，不能成为页面加载依赖。本协议不把第三方主题复制到 Flash。

### 启动/切换时的固件加载算法

```text
1. 初始化能力壳、路由和独立 rescue 呈现。
2. 挂载 FFat，读取并验证 FactoryThemeHeader、`builtin.default/theme.ini`、`theme.tmb` 和 `assets.index`；失败则保持 rescue 并显示 FFat 修复诊断。
3. 以已验证的 FFat `builtin.default` 建立完整首屏。
4. 挂载 SD；失败则继续 FFat 默认主题，并把外部主题标记为暂不可用。
5. 读取 `/trailmate/packs/index/theme-state.a` 与 `theme-state.b`，选择 CRC 正确且 generation 最大的记录。
6. 若 current_theme_id 为 builtin.default 或记录不存在，继续 FFat 默认主题。
7. 在 `theme-index.a/b` 查找同 ID、版本、SHA-256 的已验证记录。
8. 规范化并打开 SD `/trailmate/packs/themes/<theme-id>/versions/<version>-<sha8>/theme.ini`。
9. 校验 ID、版本、API、能力契约、当前精确 `target_profile_id`、内存/存储预算。
10. 读取 theme.tmb 与 assets.index，验证格式、哈希、路径和每条路由的必需槽位。
11. 通过后，在帧边界把 SD 外部主题覆盖层绑定到 FFat 默认能力壳；失败则记录原因并继续 FFat 默认主题。
12. 页面打开时按需从该主题 SD 目录读取已索引资源；读失败的页面回退 FFat 默认资源/布局，绝不阻塞全局返回和 Extensions。
```

该顺序确保 SD 卡不是启动前提：FFat 正常时，当前界面在 SD 缺失、卡损坏或卡被拔出时仍完整可用。若运行中检测到活动主题的 SD 资源不可读取，主题运行时停止继续使用外部资源，在下一安全帧恢复 FFat `builtin.default`，并在 Extensions 显示“SD 主题不可用”。FFat 本身出现读错/卸载/契约不匹配时，不能承诺完整默认界面，必须进入 rescue。

## 启用、预览和回退

### 预览

预览应先采用“受限预览”而不是立即替换全局 UI：

- 在 Extensions 内用固件提供的样例能力视图渲染主题卡片、菜单和两个代表性页面；
- 预览不修改活动主题双槽状态记录；
- 预览同样运行资源和布局验证，但允许对不在当前预览范围的页面显示“将使用内置布局”；
- 用户确认“启用”前，当前主题始终生效。

### 启用事务

```text
用户点击启用
  → 再次验证已安装目录（防止存储介质被替换）
  → 写入未使用的 theme-state 槽为 pending（旧主题 + 候选主题 + 事务序号 + CRC）
  → 在 UI 帧边界停用旧主题资源引用
  → 载入候选主题的核心令牌/索引
  → 对目标 profile 的完整 route 集合执行渲染、资源、焦点与动作可达性自检
  → 写入新的 theme-state 槽为 committed，并校验 CRC/generation
  → 重建当前页面的呈现树
  → 成功；或恢复旧主题并记录失败码
```

自检至少覆盖仪表盘、一个编辑页面、一个危险确认页和 Extensions 页，以防主题仅能显示菜单却让关键交互不可用。

### 启动恢复

固件应保存 `current_theme_id`、`previous_theme_id`、`activation_txn_id` 与最近一次激活结果。启动时：

1. 如果上一事务未完成，优先恢复 `previous_theme_id`；
2. 如果当前主题不存在、哈希不一致或加载失败，进入内置主题；
3. 连续两次在主题渲染窗口内失败时，标记该主题为 `activation_failed`，不再自动重试；
4. 保留一个不可被主题改写的安全模式入口，用户可强制选择内置主题；
5. 扩展中心显示可理解的原因码，但不暴露内部绝对路径或敏感系统信息。

## 更新与卸载

### 更新

- 目录以包 ID、版本和归档 SHA-256 判断更新可用；不能只依赖目录名。
- 更新先安装成独立 staging；只有新版本完全验证后才替换旧版本目录与索引。
- 若更新的是当前主题，更新完成后仍保持旧版本激活，除非用户明确选择“安装后启用”。
- 新版本启用失败时，自动保留/恢复旧版本。

### 卸载

- 非当前主题可在确认后卸载，并在一次原子事务中移除主题目录与 installed index 记录。
- 当前主题的“卸载”操作应转译为“恢复内置主题 → 验证成功 → 卸载”，不能先删除活动资源。
- 主题包不得依赖其他可下载主题；主题内部所需的布局和资源必须随该 profile 专属包完整交付，卸载不产生主题间反向依赖图。

## 远程目录与信任模型

### 目录职责

目录只负责发现和下载元数据；固件主题注册表才负责读取已安装主题。目录条目至少包含：

- 通用包字段：ID、版本、名称、摘要、作者、大小、SHA-256、下载路径、最低固件版本和内存档位；
- 主题字段：`theme_api`、`capability_contract`、精确 `target_profile_id`、预览资源、资源预算；
- 信任字段：发布 key ID、发布签名、目录签名状态、发布/撤销状态、源提交与合并 PR；
- 用户呈现字段：标签、许可证、变更摘要和截图（目录资源同样受尺寸限制）。

### 建议的信任分级

| 来源 | 安装策略 | 扩展中心标识 |
| --- | --- | --- |
| 内置 | 永远可用，固件签名保护 | “内置” |
| 受信工程目录 | 目录签名、归档哈希、受保护 CI 发布签名、源提交与合并 PR 均可验证 | “已验证发布” |
| 受信工程侧载 | 用户从 Release/Pages 获取同一已发布 `.tmt`，验证包签名与目录摘要 | “本地安装（已验证）” |
| 无法验证 | 拒绝安装或隔离；不提供启用 | “未验证/已隔离” |

主题包没有业务权限，因此不需要 Android 式权限弹窗；页面应明确显示“无可执行代码、无网络/硬件权限”。这既是安全保证也是用户信任说明。

## 与现有包系统的迁移关系

现有安装器已经处理目录、下载、归档 SHA-256、`payload/` 解压和已安装索引。主题实现应：

1. 在包记录与目录解析中增加 `theme-bundle` 和主题专有元数据，但主题目录使用分页二进制记录流，而不是 JSON 对象树；
2. 将当前 Extensions 页面仅接受 locale/content/input 的类型筛选改为受控白名单，加入 `theme-bundle`；
3. 不改变 locale/content/input 的 payload 根、激活模型或内存加载策略；
4. 将主题专有安装后验证、`theme-index.a/b` 写入放在通用“归档校验成功、提交前”的钩子中，而不是在页面代码中临时判断；
5. 主题启用属于 `ui_theme_registry` 的事务，不属于“下载/解压”的职责。

这样包仓库保持“包从哪里来、如何安全安装”，主题运行时保持“安装的主题是否可以呈现”，Extensions 页面只是“向用户展示和发起操作”。

## 可观测性与用户可见诊断

必须为每个关键阶段提供短状态码与友好说明，例如：

| 代码 | 面向用户的说明 | 技术含义 |
| --- | --- | --- |
| `THEME-100` | 此主题不适用于当前设备。 | `target_profile_id` 不匹配。 |
| `THEME-110` | 固件版本或主题接口过旧。 | `min_firmware_version`/API 契约不满足。 |
| `THEME-120` | 设备存储或内存不足。 | 预检预算失败。 |
| `THEME-130` | 下载文件校验失败，未安装。 | SHA-256/签名/归档结构失败。 |
| `THEME-140` | 主题布局不完整，已拒绝启用。 | 必需槽位/动作可达性失败。 |
| `THEME-150` | 主题无法安全启用，已恢复上一个主题。 | 激活自检或渲染失败。 |

日志可记录包 ID、版本、错误码和非敏感计数；禁止记录聊天文本、凭据、密钥、未脱敏设置或完整下载 URL 中可能的令牌。
