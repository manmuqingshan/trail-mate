# 地图目标与覆盖层接入契约

状态：基于现有源码的设计候选，未开发，仍需实施前影响分析。

## 1. 核查事实

现有[Map viewport](../../../../modules/ui_shared/include/ui/widgets/map/map_viewport.h)提供focus_point、zoom、平移和覆盖绘制。它是视图运行组件，focus_point不能自动当作持久导航目标。

现有[GPS页面运行时](../../../../modules/ui_shared/src/ui/screens/gps/gps_page_runtime.cpp)包含路线文件、偏航和路线展示状态。仓库已有明确的[路线导航领域缺失问题](../../../review/issues/route-navigation-domain-model-missing.md)，指出navigation session/policy owner尚未形成。当前没有证据支持“只调用现成setTarget即可”的说法。

因此首版明确把Geocaching的“前往”定义为**单个已验证点的目标引导：地图显示目标、自身位置、直线距离和方位**，不冒充自动规划路线或逐路口导航。不会把现有路线偏航逻辑复制进Geocaching页面。

## 2. 拟议所有者

建议在已有core_gps中增加单点目标会话职责，独立于Geocaching协议模块；不是在ui_shared内增加导航全局变量。它只接受经上游校验的目标坐标和不透明来源引用，消费既有有效定位快照。

Geocaching拥有作者对象和版本；目标会话拥有“用户当前要去哪个坐标”；地图模型拥有视口；三者不同。用户看另一个地图点不自动改变目标，更新作者记录不自动改变正在使用的目标。

逻辑TargetSession输入：本机session_id、source_kind=geocache、cache_id32、revision_hash32、lat_e7、lon_e7、用户可读名称。存储私有来源引用不改变GPX或线上格式。

## 3. 动作与状态

| 动作 | 前提 | 结果 |
| --- | --- | --- |
| 在地图查看 | 有合法摘要坐标即可 | 只居中/选中，不开始引导 |
| 前往 | 完整对象已验签且active，无已证实冲突 | 新建或明确替换单点目标会话 |
| 替换已有目标 | 用户确认替换 | 保留原返回上下文，切换会话 |
| 停止引导 | 有活动会话 | 清除目标会话，不删GPX或个人记录 |
| 查看目标 | 有会话 | 地图居中目标，保留引导 |
| 更新到作者新坐标 | 用户明确同意，新的对象已验证 | 用新hash/坐标更新会话 |

状态：Inactive、WaitingForFix、Guiding、Suspended。无有效定位时保留目标并显示等待定位，不输出假0米。暂停可用于位置不可用或应用生命周期停用；不修改作者维护状态。

此单点引导不自动判断“找到宝藏”。找到记录仍由用户填写；GPS接近坐标不证明找到实体容器。v1不定义自动到达事件或偏航阈值，避免擅自把路线策略引入点引导。

## 4. 距离与方位呈现

使用核心定位/地理计算能力输出米制直线距离、真北方位、定位有效性和新鲜度。若复用的算法有精度/极点限制，实施时必须形成同一核心契约并验证，不让LVGL和GTK分别实现。

地图方向箭头必须区分真北方位与设备朝向：没有有效航向时显示“目标方位xxx°”和北向参考，不画一个伪装成设备朝向校正的箭头。底图缺失时仍可给坐标和直线方位，不显示道路路线。

正在引导时收到disabled/archived/冲突更新，显示目标状态警示，允许停止或阅读；不悄悄清除或移动目标。用户选择继续查看旧目标时明确版本已旧，不把它显示成当前可寻找状态。

## 5. 32项覆盖层的确定优先级候选

覆盖组合器先裁剪不可见候选（自身/活动目标允许屏外方向提示），再按下列顺序填入有界snapshot：

1. 自身位置：最多1。
2. 活动引导目标：最多1。
3. 当前用户选中项：最多1；与目标同对象时合并，不重复占槽。
4. 现有警告、测距锚点：保持必要工具反馈，按稳定类型和ID排序。
5. 队伍成员及既有路线/轨迹点：按当前视口距离及稳定ID排序。
6. 藏宝点候选：优先已下载active，再未下载active，再disabled；各组按视口中心距离及完整ID排序。

总数超过32标truncated。archived默认不显示，用户显式过滤查看时可进入第6组末尾。作者冲突点不进入普通发现覆盖；用户在冲突详情明确地图查看时作为选中项警示显示。

这项优先级会影响现有覆盖行为，必须在真正改造MapOverlaySnapshotSource/projector前做impact并评审，不能直接把其他业务所有权搬到Geocaching。当前是具体候选，不声称现有代码已经实现上述排序。

地图选择采用11的generation+slot引用，解析到完整ID/hash后再开详情。sort顺序或过滤变化会发布新generation，使旧slot失效；不会将稳定ID截断为32位。

## 6. 页面打开与恢复

从列表详情“前往”：业务验证对象 → 目标owner接受意图 → 保存返回route/选中ID → 通过现有页面绑定打开Map → viewport显示目标和自身。地图打开失败时保持原详情并报告，不宣称已经切换页面；目标是否保留应显式提示并允许停止。

从Map查看摘要详情后返回，恢复视口和选中点；这条路径不建立目标会话。地图平移不会改变活动目标，点击另一点也不会自动替换。

重启后默认恢复目标为Suspended，显示“恢复上次目标”入口，由用户确认重新开始引导；不因开机就自动导航。恢复引用必须再次确认本地GPX及版本状态，文件外部编辑不能被当作原已验证目标。

## 7. 验收

MAP01：只查看摘要不建立目标；MAP02：无GPS前往保留目标但不输出假距离；MAP03：平移/点选不改变目标；MAP04：新坐标需明确切换；MAP05：附近不自动标找到；MAP06：超过32项仍保留自身/目标并标截断；MAP07：重排后的旧slot被拒绝；MAP08：重启只恢复暂停态；MAP09：无航向显示真北参考不伪装机身方向；MAP10：不依赖私人路线文件才能导航到公开点。

本次核查解决“导航owner已有还是缺失”的不确定性：它目前是需新增的单点会话职责，不是已经存在的完整接口。后续代码工作仍要遵守GitNexus影响分析和现有GPS领域边界。
