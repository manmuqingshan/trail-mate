# 公共藏宝点发布、发现与离线寻宝交互设计

状态：**待用户评审；未授权界面或协议开发**  
文档版本：0.2.0-draft；对应拟议线协议：1  
关联：[设计入口](./README.md) · [协议规范](./01-协议规范.md) · [公共发现与传播](./04-公共发现与传播.md) · [评审与验收](./03-评审与验收.md)

## 1. 已纠正的产品基线

配套 [UML 与坐标流转](./05-UML与坐标流转.md)用端到端时序图区分“地图上看见摘要坐标”和“已经下载并验证原作者内容”，并说明更新、撤下和断网后的显示变化。

**玩家把藏宝点公开发布到 Reticulum 上的公共藏宝点网络，其他兼容终端自动发现并下载。发布者不选收件人，读者不必先添加作者或内容来源。**

0.1 草案中“选择来源后发布”“先添加来源再发现”的主流程已废弃。底层目的地地址属于协议路由和诊断，不得重新成为发布者选择读者的产品入口。

本稿定义行为、状态和信息，不指定像素布局、屏幕坐标或代码模块。触屏、键盘和旋钮设备按现有 UX Profile 呈现相同语义。

## 2. 信息架构

~~~text
寻宝
├─ 发现藏宝点
│  ├─ 公共发现状态
│  ├─ 选择地图区域 / 过滤 / 刷新
│  └─ 合并摘要列表 / 地图 → 下载详情
├─ 已下载
│  └─ 详情 → 导航 / 提示 / 个人记录 / 检查更新 / 删除副本
├─ 我的发布
│  ├─ 新建草稿 → 预览 → 公开发布
│  └─ 已发布 → 编辑新版本 / 暂停 / 恢复 / 撤下 / 传播状态
└─ 活动记录
   ├─ 发布、查询、下载的总体状态
   └─ 高级详情 → 公共目录、底层请求、错误与诊断
~~~

公共目录地址、候选选择和各节点结果留在高级信息，普通路径不要求用户管理它们。私人聊天联系人列表不能用作公共目录列表。

## 3. 第一次使用和自动发现

1. 用户进入寻宝，阅读一次说明：“公开藏宝点可被其他兼容终端发现与下载；查询区域会发送给公共目录。”
2. 启用后接收合法服务 announce，验证目录身份和 LXMF 地址绑定，自动请求 capabilities。
3. 同时可以使用此前持久保存的目录地址。没有地址且未收到 announce 时显示“正在发现公共目录”。
4. 确认可用目录后，自动查询用户选定区域。默认区域来自本机地图视图，不擅自上传轨迹。
5. 无目录可达时显示“暂未发现可用的公共目录”，已下载内容照常可用；可保留草稿但不能宣称发布成功。
6. 高级诊断可添加替代种子辅助网络接入，普通路径不要求填写地址。

~~~mermaid
sequenceDiagram
    actor 用户
    participant 终端
    participant Reticulum
    participant 公共目录
    公共目录->>Reticulum: 专用服务 announce
    Reticulum-->>终端: 合法目录发现信息
    终端->>公共目录: LXMF capabilities
    公共目录-->>终端: 200 公共目录能力

    终端->>公共目录: LXMF query
    公共目录-->>终端: 公开摘要
    终端-->>用户: 合并的藏宝点列表
~~~

历史通信成功不表示当前在线；目录名字不代表信任。完整目录地址和最近能力确认时间可在高级信息查看。

## 4. 新建、预览与公开发布

### 4.1 创建草稿

填写名称、坐标、介绍、提示、难度、地形、容器大小。默认 active，可选择首次 disabled。坐标从地图选取，或明确点击“使用当前位置”；不后台采集位置。

编辑器按 UTF-8 字节计数，遵守单字段与总上限；超限指出具体字段，不裁剪正文。中文不能按“一字一字节”计算。签名前转换 CR/CRLF 为 LF。

草稿只存在本机，不是公开对象。确定作者、创建 nonce 和时间后生成稳定 ID；重试或换入口不能重新生成。签名后原版本不可变，再编辑形成新版本。

### 4.2 发布确认

显示名称、位置、状态、作者身份、版本和详情大小。主按钮为**公开发布**，没有收件人选择。必须说明：

- 这个点将进入公共目录，任何支持该功能的 Reticulum 终端都可以发现和下载。
- 内容可能被多个目录保存和继续传播；撤下不能删除所有旧副本。
- 网络离线或分区时传播会延迟；请求可能在停止等待后才送达。

大小是内容字节数，不是精确空口流量。

### 4.3 自动公开接纳

应用按传播文档自动选择入口，有界尝试，目标取得两个不同目录确认。一个目录确认即满足最低公开接纳，不代表全网同步。

| 已知事实 | 主界面文案 | 后续动作 |
| --- | --- | --- |
| 排队且未发现入口 | 等待公共目录 | 等待、取消未发送任务 |
| 正在联系入口 | 正在公开发布 | 查看、停止后续尝试 |
| LXMF 交付，无应用结果 | 等待公开接纳确认 | 按策略等待或重试 |
| 一个目录 200 | 已公开发布，继续传播中 | 自动联系第二入口 |
| 两个目录 200 | 已公开发布，已有两个目录接纳 | 查看传播信息 |
| 尝试耗尽且无 200 | 尚未确认公开发布 | 稍后重试、保留任务 |
| 部分成功、部分拒绝 | 已公开发布，部分目录未接纳 | 保留整体接纳事实，显示局部原因 |
| 签名/格式错误 | 标点验证失败，尚未公开 | 返回编辑或诊断 |
| 目录报告版本冲突 | 某目录报告版本冲突 | 获取证据，不只加大版本号 |

同一对象进入多个目录仍是一条“我的发布”。目录结果是发布任务的子请求，不要求用户逐个处理。

~~~mermaid
sequenceDiagram
    actor 作者
    participant 客户端
    participant 目录A
    participant 目录B
    作者->>客户端: 公开发布
    客户端->>客户端: 固定对象、签名和发布任务
    客户端->>目录A: LXMF publish（自动入口）
    目录A->>目录A: 提交对象、公开索引、同步日志、结果
    目录A-->>客户端: 200 公开接纳
    客户端-->>作者: 已公开发布，继续传播中
    客户端->>目录B: 相同对象，不同请求 ID
    目录B-->>客户端: 200 公开接纳
    客户端-->>作者: 已有两个目录接纳
~~~

### 4.4 停止等待和确认丢失

尚未交给 LXMF 的发布可以取消。一旦子请求入网，只能停止新尝试和重试，不能写“已撤销公开发布”。迟到 200 显示“迟到确认：已公开发布”。

某入口已保存而响应丢失时，原 request_id 重试重放结果；换入口用新 ID。不能因超时重新生成标点或宣布“无人能看到”。公开撤下需要另一个签名版本。

## 5. 公共发现与分页

发现以区域为主，不以来源选择为主。应用自动向有限数量的公共目录串行查询并合并结果；更多目录公平轮换，不无限扫网。

摘要显示名称、坐标或本地计算距离、难度、地形、状态、版本和详情大小。标记“目录摘要，详情尚未验证”；目录的 LXMF 签名不等于作者对象已经验证。

- 同 ID/hash 合并，保留多个提供者用于自动故障转移。
- 同 ID 不同摘要版本保留线索，未经完整对象验证不宣布作者冲突。
- 加载更多继续各目录自己的快照，没有跨目录全局游标。
- 某目录返回 410，重查该目录，不丢弃其他目录结果；显示查询已更新。
- 区域、状态或预算改变后重新建立对应查询。
- 空结果显示“当前已发现的公共目录没有匹配结果”，不说“全网没有宝藏”。

跨日期变更线区域拆成两个 bbox，按 ID 合并。距离排序只针对已收到的结果，不保证未加载的点更远。

## 6. 下载与离线使用

### 6.1 下载详情

点击摘要的“下载详情”，应用自动向提供该精确 hash 的目录 get；失败可尝试其他已知提供者，用户不指定下载地址。

收到后：外层验证 → 作者签名 → ID/hash → 字段和版本规则 → 摘要匹配 → 本地持久保存。过程显示下载、验证、保存；落盘后才显示“已下载，可离线使用”。

目录已更新但仍提供选定 hash 时按所选历史版本保存并标记。指定版本不再可取时提示“该版本暂不可下载”，用户可以刷新列表或明确获取最新版本，不暗换内容。

批量下载建议最多 20 个，逐点串行、分别保存结果。显示“完成 3/8，失败 1，等待 4”，不把部分完成当全成功。

### 6.2 已下载详情

必须可查看正文、位置、折叠提示、难度、地形、容器大小、维护状态、作者指纹、版本/hash、提供者、本地验证时间与作者声明时间。

作者时间未知显示“未提供时间”；无定位不显示假 0 米。已有底图与定位可离线导航；缺少底图显示“底图未准备”，不解释成藏宝点下载失败。

提示折叠只是避免剧透，不称解密。作者 active/disabled/archived 与个人“找到/没找到”是独立维度。个人日志按 cache_id 关联，记录参考版本，只保存在本地，不发 LXMF。

### 6.3 删除与取消

删除本地副本不生成公开撤下、不删除作者数据；有个人记录时保留记录条目，可另行明确删除。移除缓存目录不删除下载内容。

取消批量任务停止新请求；在途响应可验证，但明确取消保存的项不自动导入。保留有限迟到记录，不重启任务，不关闭其他业务共用的底层连接。

## 7. 更新、暂停与公开撤下

### 7.1 下载者检查更新

点击“检查更新”，应用自动向可用目录 get(latest,known_hash)，必要时联系其他目录并按作者签名和版本合并。304 只表示该目录已知版本未变；旧结果不能回退本地较新版本。

404 表示某目录不提供，保留本地副本，不当成撤下。公共目录承担全库 sync；普通终端按 ID 检查即可发现移出原查询区域的点。

### 7.2 作者编辑

从已签名版本编辑新草稿，显示 vN → vN+1，签名绑定前驱。存在未确认发布时提醒它仍可能送达，默认先处理前次结果再提交下一版本。

同一身份多设备没有分布式写锁；建议一个设备负责写入，换设备前同步最新记录与身份备份。密钥丢失不能由目录代签，也不能凭显示名恢复所有权。

已签名版本即使未发布也不得把同一revision重新签成不同内容。保留本机签发记录，继续修改时递增版本；废弃未发布版本可以形成历史跳号快照。界面区分“已签名未提交”“已入网未确认”“已公开接纳”，不能通过删除任务释放版本号。详见10 §5。

### 7.3 暂停、恢复、撤下

| 动作 | 作者状态 | 传播 |
| --- | --- | --- |
| 暂停 | disabled | 自动公共发布新版本，再由目录 sync 传播 |
| 恢复 | active | 仅 disabled 可恢复，同上 |
| 撤下 | archived | 签名终止版本，同上，不恢复此 ID |

撤下确认：“此 ID 撤下后不再恢复。状态会向公共目录传播，但无法删除已经保存的旧副本。”

“已撤下”基于至少一个入口接纳撤下版本，并标记继续传播中，不能宣称全网移除。离线目录可能仍显示旧状态，因此详情保留最后检查时间。

## 8. 传播状态与诊断

普通用户看到公开接纳、继续传播、暂不可达和已下载；高级信息展示目录数量、入口确认、地址和同步事实。

目录自动 sync 不需要作者点击转发。目录 A 的确认不证明 B 已复制；B 的确认或成功读取才是 B 的事实。没有全网节点总数，不能显示“全网同步百分比”。

~~~mermaid
sequenceDiagram

    participant 目录A
    participant 目录B
~~~

## 9. 冲突与异常

获得矛盾的有效作者记录才本地确认冲突并冻结自动更新。只收到目录报告时显示“目录报告冲突，尚未取得全部证据”。公共浏览隐藏已确认冲突点，已下载列表保留警示与个人记录。

历史元数据提示矛盾但缺少旧原文时显示“历史待核实”，保留当前已下载副本并停止自动升级；它不同于已证实作者分叉。详情可查看核实状态，不生成无法独立验签的公共冲突结论。

冲突详情展示版本/hash、提供者、接收时间，不提供按时间覆盖或加大版本号解决按钮。v1 人工新建 ID 迁移，旧 ID 保持冲突。

| 异常 | 用户反馈 | 恢复 |
| --- | --- | --- |
| 无公共目录 | 等待公共目录 | 保留草稿、已下载、任务 |
| 请求入网无结果 | 尚未确认公开接纳 | 保留 ID，有界入口故障转移 |
| 某目录拒绝 | 部分目录未接纳 / 尚未接纳 | 尝试其他入口，不回退私聊 |
| 目录彼此隔离 | 传播可能延迟 | 重连自动 sync，无需添加作者 |
| sync 日志过期 | 高级信息显示重建同步 | 目录重建基线，不删除旧对象 |
| 摘要与正文不同 | 目录信息与详情不一致 | 不完成该摘要下载，保留诊断 |
| 作者签名无效 | 内容验证失败 | 不导入，保留旧副本 |
| 本地存储满 | 接收完成但保存失败 | 保留旧版本和笔记 |
| 作者密钥不可用 | 当前身份无法修改 | 不由目录代签 |
| 迟到结果 | 迟到确认 | 不恢复取消的分页或批量任务 |

## 10. 多维状态与重启恢复

~~~mermaid
stateDiagram-v2
    [*] --> 等待公共入口
    等待公共入口 --> 投递中: 自动选择目录
    投递中 --> 等待应用结果: LXMF交付事实
    投递中 --> 入口结果已记录: 有效应用响应先到
    等待应用结果 --> 入口结果已记录: 有效响应
    投递中 --> 尚未确认: 网络受阻或提醒到期
    等待应用结果 --> 尚未确认: 提醒到期
    尚未确认 --> 投递中: 原请求重试或新入口子请求
    尚未确认 --> 入口结果已记录: 迟到响应
    投递中 --> 停止后续尝试: 用户停止
    等待应用结果 --> 停止后续尝试: 用户停止
    尚未确认 --> 停止后续尝试: 用户停止
    停止后续尝试 --> 迟到结果已记录: 有效响应
~~~

每个入口请求独立持久记录；发布任务汇总至少一个 200 为最低公开接纳。入口终态也可能是拒绝。晚到的底层失败回调不能覆盖已确认的应用成功。

本地内容另有“仅摘要 → 下载中 → 验证中 → 保存中 → 已下载”。作者状态、个人找到状态、传输状态、公开接纳与本地下载状态不得用一个枚举覆盖。

重启恢复草稿、签名原文、发布任务及其子请求 ID、已下载对象和个人记录。不能因为重启重新生成 nonce、丢掉已确认结果或把未知状态当成功。

## 11. 公共目录管理（可选设备角色）

若批准某设备提供目录，显示公开角色、存储配额、保留承诺、自动发现同伴、同步进度与反滥用规则。它不是私人好友共享开关。

不允许“仅好友可见”却仍宣告公共角色。关闭目录必须显示未到期承诺并停止新接纳，不能后台销毁仍需恢复的请求和对象。具体关闭/迁移运行方案在该角色实现前另行评审，不把目录运行能力默认放进所有终端。

## 12. 交互验收底线

- 不知道作者地址的新终端仍能公共发现。
- 发布按钮无收件人选择，入口失败不回退私聊。
- 一个入口确认表示公开接纳，不表示所有终端已经收到。
- 小屏可拆页，公开性、状态和作者信息必须可达。
- UI 只提交意图和展示事实，不解析 LXMF 或修改协议账本。
- 未验签摘要不冒充已下载，旧响应不回退有效新版本。
- 本次只写交互规范，没有实现界面、原型或运行界面测试。
