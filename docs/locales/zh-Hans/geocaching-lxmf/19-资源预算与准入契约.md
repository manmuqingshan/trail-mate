# 资源预算、准入与调度契约

状态：设计候选，未测量固件资源，待评审。适用设备公共客户端；公共目录另有服务预算。

## 1. 预算的三个层次

1. 协议硬上限：决定线上合法性，各实现不能自行降低后仍宣称完整兼容。
2. 产品默认：队列数量、候选数量、并发和缓存策略，可按目标配置但必须显示容量不足。
3. 平台准入：启动时和运行中检查真实内存、存储与协议栈能力。不满足时保持功能受限/不可用，不靠栈上大数组或截断数据勉强运行。

已读[协议运行预算政策](../../../protocol_runtime_budget_policy.md)与[RuntimeBudget](../../../../platform/esp/arduino_common/include/platform/esp/arduino_common/chat/infra/lxmf/lxmf_runtime_budget.h)：公共发现受唤醒/空闲和实时业务约束，接口选择由已有owner决定。本功能不绕过这些规则直接开第二路无线收包或在屏幕回调中扫描全网。

## 2. 硬上限汇总

| 对象 | 上限 | 超限处理 |
| --- | --- | --- |
| CUSTOM_DATA | 8192字节，解压后 | 按01拒绝，不先分配声明长度 |
| 原始CacheRecord | 4096字节 | 413/本地验证失败 |
| CMP1 SignedCache | 4166字节 | 不拆成私有线上分片 |
| 单响应预算 | 512..8192字节 | 整体编码后核对，不只算正文 |
| query/sync页 | ≤64项且受字节预算限制 | 分页或413，不截断一项 |
| 服务announce应用数据 | 96字节 | 拒绝非法候选 |
| 单点生成GPX | 65536字节 | 超限视为生成/配置错误，不截断合法原文 |
| 导入GPX | 8MiB、1000个wpt候选限制 | 明确范围受限，不声称全部导入 |
| 地图覆盖snapshot | 当前设计32项 | 优先级过滤并标truncated，不加载全库 |

GPX上限为本地格式profile，不是LXMF上限。XML转义、Base64和可读描述重复计入文件大小。存储不能仅预留4166字节就启动GPX安装。

## 3. 客户端默认工作集

| 项目 | 首版候选默认 | 到达容量时 |
| --- | --- | --- |
| 公共目录候选 | 32 | 12中的老化/淘汰；在途不可直接删除 |
| 同时主动网络操作 | 1 | 其他用户任务有界排队 |
| 活跃用户任务 | 20 | 返回Busy，不覆盖旧任务 |
| 待发送命令槽 | 20个小型句柄 | 不复制20份8KiB载荷进RAM |
| 接收应用载荷池 | 2×8192字节 | 背压或栈持久待处理，不丢失已承诺接收 |
| GPX流式IO工作区 | 2×1024字节 | 不在RAM拼接整64KiB文件 |
| 原记录工作区 | 1×4096字节 | 与任务串行调度，不开每请求独立大栈对象 |
| 列表展示页 | 20条摘要 | 显示窗口/分页，不把全部目录放进UI |
| 查询响应缓存 | 每活跃查询最多3个来源页面 | 完成持久处理后释放，历史页按磁盘预算保留 |

前三个固定字节工作区合计22528字节，但这不是总内存承诺：LXMF栈resource、密码库、XML解析器、UI快照、任务元数据与文件系统缓存另计。必须测得总峰值和栈高水位，不能用这张表声明某板已经可运行。

接收池与传输owner可以共享已批准的lease池以减少复制，但共享后须保持11所有权契约，不能隐式复用仍被消费者读取的槽位。

## 4. 磁盘准入

每次下载前预留最坏新GPX64KiB、旧文件备份64KiB、安装日志/索引更新至少16KiB，即每次安装至少144KiB操作余量，另加平台文件系统保留空间。这里是工作余量，不含现存文件总量或checkpoint压缩空间。原80KiB值随GPX最大转义案例检查修正，详见17 §7。

压缩必须额外容纳一个完整新checkpoint和仍需恢复的旧checkpoint/日志。计算实际预计大小再准入，不能一边删除旧恢复链一边腾空间。

辅助value最大32768字节，checkpoint页和事务payload最大65536字节（14定义），均流式编码/读写，不新增同等大小的任务栈数组。最大Outgoing请求与响应同时保留会超过16KiB，因此不能继续使用旧16KiB value/检查点页假设。

默认用户内容软预算64MiB，辅助状态软预算32MiB；这是候选配置，不预占整段磁盘。达到软预算先停止新下载/查询持久化，提示清理或提高预算。不得自动删除个人笔记、未确认请求、作者签发历史或未到期保留义务。

普通GPX文件由用户可见地管理，.state重建不能掩盖内容删除。GPX导入使用流式读取，源文件之外还需为每个接受点做独立准入；允许部分成功并明确剩余项未导入。

## 5. 屏幕、无线与实时业务

应用只提交轻量发现意图给既有预算owner。普通announce继续按原政策延迟处理；用户明确进入寻宝并查询时，候选能力检查与请求属于用户任务，但也不能提高无线包预算或抢占实时通话资源。

实时通话/资源租约阻止新后台操作时，暂停新发现、自动第二入口与同步维护；已进入栈的消息仍由栈负责安全处理。当前页面显示“等待资源”，不把暂停当网络不支持。

Auto/LoRa/Wi-Fi承载选择使用现有统一owner；Geocaching不能为追目录同时启用被策略禁用的接口。screen-off也不代表可无限收包，仍遵守已有维护预算。

每次应用调度只处理一个有界工作项：一个事件、一个记录验证阶段或一个IO块。耗时密码学操作若不能分步，应在适当后台上下文执行；不能占用LVGL事件循环。具体耗时需实测，禁止预先宣称固定毫秒完成。

## 6. 降级规则

| 原因 | 页面能力 | 在线任务 |
| --- | --- | --- |
| Reticulum未选用或未就绪 | 已下载GPX和个人内容仍可读 | 暂停，不清空账本 |
| 无可写SD | 已有可读内容可浏览 | 禁止新持久下载/发布签发 |
| 存储Hydrating | 显示恢复中 | 不入新写入事务 |
| 收包池满 | 保留现有任务 | 背压，不能ACK后静默丢弃 |
| 超软预算 | 显示容量提示 | 不接纳新写，不删除承诺 |
| 目标无法处理硬上限 | 明确不支持此profile | 不宣告完整v1并截断数据 |
| 仅显示资源不足 | 简化可见项、保留truncated | 不改网络对象或作者记录 |

## 7. 资源验收

R01：两份最大入站同时到达，池所有权正确；R02：20任务排队不复制20份载荷；R03：GPX最坏转义输出不溢出；R04：磁盘余量不足时不先删除旧文件；R05：checkpoint空间不足保持旧恢复链；R06：通话期间后台发现不绕过owner；R07：切换承载不启用禁用接口；R08：拔卡保留任务且旧lease不会写到新卷；R09：地图超32项明确截断；R10：栈高水位/堆峰值/文件句柄数有实际测量记录。

R01–R09现在是验收契约，R10只能在获准实施后验证。本稿把候选默认明确化，不假装代替硬件测量。
