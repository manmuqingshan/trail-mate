# GPX字段映射、外部编辑与安装契约

状态：待评审设计候选，未实现。本文具体化16；不改变LXMF中的签名记录编码。

## 1. 文件范围与标识

设备生成UTF-8、XML 1.0、GPX 1.1，根namespace为 `http://www.topografix.com/GPX/1/1`，根属性version="1.1"、creator="Trail Mate"。该URL是XML命名空间标识，不是联网下载要求。解析文件不得为schemaLocation或扩展地址自动联网。

一个正式下载文件只含一个wpt；批量导出可以多wpt。文件名使用完整cache_id小写hex，显示名保留在name中。用户原始imports文件不自动改名或覆盖。设备正式下载目录与用户输入目录分开，避免原文件被后台更新破坏。

## 2. 标准waypoint映射

XML文本必须使用标准序列化转义：至少将&写成&amp;、<写成&lt;，不得拼接未转义作者内容作为XML标签；实现可转义>。属性使用带引号的标准编码。描述/提示的LF与TAB放在元素文本中保留，不能移到XML属性后被空白归一化。禁止U+FFFE/U+FFFF与01禁止的控制字符，接收有效UTF-8不等于保证XML1.0可表示。

比较外部文件时按XML解析后的文本值，不比较CDATA、实体写法和属性顺序；读入XML解析器归一化CRLF为LF与原规范一致。生成器不额外裁掉作者前后空白，也不把内容误当HTML解析。遇到不可表示字符在签发前明确拒绝，不下载后静默剔除。

生成元素按GPX schema顺序，使用以下子集：time（可选）、name、cmt、desc、src、sym、type、extensions；不得按字典顺序写XML。

| 字段 | 生成值 | 读回校验 |
| --- | --- | --- |
| wpt/@lat、@lon | e7整数转换成小数点后的7位十进制度，不使用本地化逗号 | 十进制解析后量化回e7与原文比较 |
| time | updated_at非0则取updated_at，否则created_at非0取其值，否则省略 | UTC ISO8601，时区归一后比较秒值 |
| name | 原name | XML解码后按Unicode文本比较，不自行归一化 |
| cmt | 原hint，空时空元素或省略 | 对应原提示；文本未加密 |
| desc | 第3节可读说明块 | 与规范生成的说明文本比较 |
| src | 固定 `Reticulum Geocaching` | 描述数据来源，不冒充其他平台 |
| sym | 固定 `Geocache` | 仅符号提示，不保证软件开启寻宝模式 |
| type | 固定 `Geocache|Traditional Cache` | 仅类型提示；不得伪造平台缓存ID |

如果作者声明时间不在实现日期库支持范围内，编码器必须使用能完整表示协议范围的转换或返回本地格式生成错误，不能悄悄写1970。外部普通GPX时间不合法时该点进入导入警告，不能影响其他独立wpt。

## 3. 普通软件可读的说明块

desc将原介绍和必要寻宝信息一起呈现，使忽略扩展的软件仍能阅读。生成规则固定为以下文本，LF换行，标签使用稳定ASCII，值为对应值；XML层按规则转义：

```text
<原description，可为空>

--- Reticulum Geocaching ---
Cache-ID: <64位小写hex>
Revision: <十进制revision>
State: <active|disabled|archived>
Difficulty: <1.0至5.0，固定1位小数>
Terrain: <1.0至5.0，固定1位小数>
Container: <not-specified|micro|small|regular|large|other>
Hint: <原hint，可含LF>
```

原description之后始终追加两个LF再写分隔线；hint后不额外追加LF。提示也写入cmt便于简易工具显示。此重复是文件兼容表示，不是两份独立真相；读回时按原签名对象重新生成desc核对。

不能通过解析用户任意desc中的Cache-ID标签来取得可信身份。只有有效的签名扩展能恢复协议对象；没有扩展时上述说明只是文本。

## 4. 作者原文扩展候选

推荐namespace候选 `urn:trailmate:geocaching:gpx:1`，前缀tm可任意，按namespace URI而非前缀判断。正式名称仍由13的命名评审一并批准。

```xml
<extensions>
  <tm:record xmlns:tm="urn:trailmate:geocaching:gpx:1" version="1">
    <tm:payload encoding="base64">...</tm:payload>
    <tm:signature encoding="base64">...</tm:signature>
  </tm:record>
</extensions>
```

payload是原始record_bytes，不是CMP1(SignedCache)整体；signature为原64字节作者签名。生成使用RFC4648标准Base64字母表及必要的=填充，不换行；读取允许XML空白字符后严格解码，不接受其他字符、重复payload/signature、多份tm:record或尾随垃圾。payload解码后≤4096，signature恰好64；总文件上限见第7节。

应用namespace版本=1仅表示本扩展的字段布局，不自动改变记录schema。从payload恢复作者公钥、ID、hash和全部字段；扩展不另外复制一个可与原文矛盾的ID属性。

第三方可以忽略此扩展读取标准wpt。GPX根schema验证不等于tm扩展有效，必须再做结构、大小、原作者签名和映射一致性验证。

默认寻宝语义扩展采用[21的Groundspeak1.0.1兼容配置](./21-寻宝扩展兼容配置.md)，与tm:record并列，不能代替它。外部修改其中的难度/提示/维护状态也须参与映射一致性校验。

## 5. 四种导入身份

| 分类 | 条件 | 可做的动作 |
| --- | --- | --- |
| VerifiedPublic | 扩展合法、验签有效、标准可见字段映射一致 | 恢复该ID/版本的公开对象，按版本规则接纳 |
| EditedExternal | 扩展验签有效，但坐标/名称/cmt/desc/time与原文不一致 | 保留外部文件；作为本地编辑点查看，不能更新原ID的已验证版本 |
| PlainWaypoint | 无本应用扩展 | 作为普通GPX点导入；来源未验证 |
| InvalidExtension | 声明本扩展但结构或签名无效 | 报告验证失败；用户可明确选择仅导入基础wpt，不能静默降级 |

sym/type/src是显示提示，外部软件改它们不改变作者内容；不作为签名冲突依据。XML缩进、属性顺序、namespace前缀、等价实体转义不影响语义。标准字段缺失或内容改变不得从签名原文悄悄填回并覆盖用户文件。

未知扩展允许有界跳过并保留在原输入文件中，设备生成新公开对象时不把任意扩展带上网络。未知内容不执行脚本、网络加载或文件访问。

外部编辑若要公开：用户明确选择“作为我的新藏宝点发布”，创建自己的新ID和签名，来源备注可本地保留。不从普通GPX中提取别人ID来赋予编辑权。

## 6. 重复与多点

导入多wpt文件时逐点独立解析和反馈，记录文件摘要hash与wpt序号作为本地导入定位，不作为公开cache_id。基础字段合法的点可以导入，其他点显示失败；不因一个坏点放弃全部文件，也不忽略整文件XML结构错误。

VerifiedPublic以完整ID/hash去重并保留来源文件引用。普通点不因坐标相同就自动合并：同一地点可以有不同宝藏。再次导入同一文件相同序号且内容相同可提示已导入，用户可明确保留副本。文件内容变化后应重新比较而非只看文件名。

同ID不同有效签名版本执行现有规则；外部编辑与原文不一致不是作者分叉，因为该编辑内容没有原作者的新签名。

## 7. 解析与资源边界

单个设备生成GPX文件≤65536字节；XML转义和Base64开销计入，不能直接沿用4096原文上限。原32768候选因边界检查不足已修正，不能要求合法协议正文为了保存而被截断。批量导入文件候选上限8MiB、1000个wpt，流式读取；超过时明确报告范围限制，允许用户拆分，不把后续点悄悄标为成功。

计算依据：名称最多出现2份、描述2份、提示3份；按每输入字节最多6字节转义保守计，文本上界为(2×96+2×2048+3×512)×6=34944字节；原文Base64≤5464、签名Base64=88；固定标签/说明/ID等保留8192字节，总计48688，小于64KiB。生成器固定布局仍须核对实际长度，不可无限增加缩进或扩展。

对现有GPX样例用最大长度ampersand文本和最大原文Base64做纯分配推演，结果36263字节，已超过32KiB；此推演不是有效签名对象，不保存为兼容样例。证明的是旧文件容量不足，而非网络记录超限。

禁止DTD、外部实体、XInclude、自动schema加载；限制XML深度16、单wpt解析工作区与本应用原文长度。未知扩展只计数跳过，不能构造整文件无界树。非法XML不能通过字符串搜索wpt片段“抢救”为已验证内容。

普通外部字段可能长于本协议上限：本地阅读可分页，重新公开前必须提示编辑到协议允许长度，不静默截短再发布。

## 8. GPX安装与恢复

保存成功需满足：下载原文已验签 → GPX生成到同卷staging → 关闭并刷新 → 重新解析校验标准字段和签名映射 → 日志记录安装意图与旧/新文件hash及generation → 受控替换目标 → 确认新文件可读取且映射正确 → 日志提交安装完成 → 更新UI。

不能假定FAT rename任意掉电均原子。替换前保留旧GPX备份及安装意图；重启发现未完成安装时用文件hash区分旧、新、损坏状态：新文件完整则完成提交；旧文件完整则保持旧状态重试；两者均坏则报告存储损坏，不能生成空GPX盖过去。备份只在新文件与完成记录均耐久后清理。

用户或电脑修改caches内文件时，下次读取/显式重新扫描按第5节重新分类，不用旧索引跳过hash检查。索引不是作者真相。更新到新网络版本前若目标文件已外部修改，保留用户版本为导入副本并请求确认，不能后台覆盖编辑。

外部软件仅复制.gpx而没有.state仍可读基础内容；本应用可以从有效扩展重建公开对象索引，但无法凭GPX恢复所有曾经的未完成请求和个人任务事实，这一限制必须在备份说明中表达。

## 9. 兼容性验证分层

| 等级 | 检查内容 | 可宣称 |

| A | GPX1.1 schema与XML合法性 | 文件符合基础格式 |
| B | 普通GPX软件实际导入，位置/名称/desc正确 | 对已测软件基础标点兼容 |

## 10. 验收项

GPX01：下载结束直接出现可读GPX；GPX02：丢弃全部扩展后坐标/name/desc仍可用；GPX03：只改XML排版保持验证；GPX04：改坐标保留旧签名产生EditedExternal；GPX05：无扩展不自动公开；GPX06：多wpt局部字段失败逐点报告；GPX07：外部实体不加载；GPX08：替换中掉电保留旧/新完整副本；GPX09：外部修改不被后台更新覆盖；GPX10：携带真实有效签名的独立实现往返，ID/hash不变。

GPX11：协议拒绝U+FFFE/U+FFFF，避免出现无法写XML的合法记录；GPX12：&、<、>、LF、TAB经XML序列化/读取保持文本语义；GPX13：前后空白和提示中换行不被trim破坏；GPX14：远端文本含标签样式时仅显示文本，不创建额外XML元素。
