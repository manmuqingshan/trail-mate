## 1. 评审方法

新增用户确认的网站功能范围见[23：GitHub Pages浏览器寻宝板块](./23-GitHubPages浏览器寻宝板块.md)，WEB01–WEB10为追加验收；具体浏览器库、WSS入口和底图方案待评审。不能将原设备阶段的审计结论视为新网页范围已经批准或实现。

当前尚未达到可依据文档启动编码的程度；新增的[设计完备性审计](./09-设计完备性审计.md)追踪实际缺口，[生命周期与恢复](./10-请求生命周期与持久恢复契约.md)的L01–L10作为本矩阵的补充。所有“已补”候选仍需跨文档推演和用户评审。

先评审产品范围，再审对象与签名，再审请求/响应，最后用异常场景走查交互。表内“推荐方案”是本稿提出的确定候选；“待评审”不表示协议有多个未选择的线上解释。

用户可以批准、修改或否决任一条。修改后先分类为范围补充、澄清、局部修正或根本变化，更新受影响文档与本表，再进入下一轮。所有条目尚未获得用户正式批准，不能自行填写“通过”。

## 3. 设计闭合性检查

| 问题 | 本稿答案 | 定义位置 |
| --- | --- | --- |
| 数据放在 LXMF 哪里？ | 0xFB 类型，0xFC 为 CMP1 二进制信封 | 协议 §4–5 |
| 不知道作者地址怎样发现？ | 专用 announce 自动发现目录，再 capabilities/query | 公共发现 §3、§5；交互 §3 |
| 能否用传播交付？ | 相同信封与业务语义，双向响应各自正常投递 | 协议 §2、§12 |
| 谁证明原作者？ | 内层完整记录与独立作者签名 | 协议 §6 |
| 地址变化会变 ID吗？ | 下载提供者地址不影响 ID；作者公共身份变化则新 ID | 协议 §6–7 |
| 收到重复发布怎么办？ | 请求结果重放 + 对象幂等 | 协议 §9、§12 |
| 同 ID重试改了内容怎么办？ | 409 request_id_reused | 协议 §12–13 |
| 下载时目录变了怎么办？ | 固定快照和精确 hash get | 协议 §10–11 |
| 来源不再提供怎么办？ | 明确 404，保留本地副本，不伪造作者撤下 | 交互 §7 |
| 结果确认丢了怎么办？ | 原 ID重试，入口子请求独立；自动尝试其他公共入口 | 交互 §4；公共发现 §4 |
| 作者撤下能否重新启用？ | v1 不允许，另建新 ID | 协议 §7；交互 §7 |
| 如何判断公开完成？ | 至少一个公共接纳，继续自动传播，无全网完成证明 | 公共发现 §4、§8 |
| 数据怎样离开首个目录？ | 公共目录自动发现同伴，sync 引用与 get 原文 | 公共发现 §6–7 |

## 4. 可读报文示例

以下符号示例另有[五种操作完整静态字节对](./examples/FIVE-OPERATIONS.md)可核对，以及[SIGNED-VECTOR](./examples/SIGNED-VECTOR.md)的原作者签名GPX。它们补足可读示意，仍非运行时互操作报告。

以下结构遵守协议位置，但 `A64`、`C32`、`H1` 等为长度明确的符号占位，**不是有效签名测试向量，不能直接发送**。它们用于人工核对交互与字段。所有数组经 CMP1 编码后放入 CUSTOM_DATA；固定类型为 `trailmate.geocache`。

| 符号 | 含义 |
| --- | --- |
| R1..R8 | 各不相同的 16 字节请求 ID |
| A64 / N16 | 作者公共身份 64 字节 / 创建 nonce 16 字节 |
| C32 | 按公式派生的 cache_id |
| H1 / H2 | 对应记录的 32 字节版本 hash |
| B1 / B2 | CMP1 编码后的记录 binary |
| S1 / S2 | 对应作者签名 64 字节 |
| SNAP / CURSOR | 16 字节快照 ID / 1..64 字节游标 |
| SIZE1 | CMP1([B1,S1]) 的实际字节长度 |

### 4.1 能力查询

```text
请求：[1, 0, 0, R1, 8192, []]
响应：[1, 1, 0, R1, 200,
       [[1], [1], [0,1,2,3,4], 8192, 4096, 64,
        604800, 2592000, 2, "示例公共目录", 1, 2592000]]
```

这是公开接纳并提供全部五项操作的目录。它不代表 Trail Mate 默认开启入站目录服务；客户端自动发现该目录，用户不把它选成私人收件人。

### 4.2 记录与发布

```text
Record1 = [1, A64, N16, 1, nil, 0,
           302500000, 1201500000,
           "林间小盒", "在步道旁寻找一个小型容器。", "留意树根附近。",
           3, 4, 2, 0, 0]
B1 = CMP1(Record1)
S1 = 按协议 §6.3 对带域的 B1 签名
C32、H1 = 按协议 §6.3 计算

请求：[1, 0, 1, R2, 512, [[B1, S1]]]
响应：[1, 1, 1, R2, 200, [C32, 1, H1, 0, 1, H1, 0]]
```

相同 R2/应用字节重发必须重放上述业务响应；使用新 R3 提交同一当前对象可得到 disposition=1。不能把一次通信的 hash 当 C32。

### 4.3 区域第一页与下一页

```text
FILTER = [[300000000,1200000000,310000000,1210000000], 3, nil, 20]
请求：[1, 0, 2, R3, 2048, [FILTER[0],3,nil,20,nil]]
响应：[1, 1, 2, R3, 200,
       [SNAP,
        [[C32,1,H1,0,302500000,1201500000,"林间小盒",3,4,2,SIZE1]],
        CURSOR, 604800]]

下一页请求：[1, 0, 2, R4, 2048, [FILTER[0],3,nil,20,CURSOR]]
```

这里假定快照还有其他项目。返回一项是为简洁示意；真实实现必须按预算和条数取可容纳的最大前缀，不能无故拆成一项一页。

### 4.4 精确下载与检查更新

```text
精确请求：[1, 0, 3, R5, 8192, [C32,H1,nil]]
响应：    [1, 1, 3, R5, 200, [[B1,S1],1,0]]

检查请求：[1, 0, 3, R6, 8192, [C32,nil,H1]]
未变化：  [1, 1, 3, R6, 304, [C32,1,H1,0]]
```

如果来源已经 v2，则 R6 回 200 和 B2/S2，而不是 304；如果来源已知冲突则回 409。精确取旧 H1 时可以返回 `is_current=0`。

### 4.5 暂停与撤下

```text
Record2 与 Record1 同作者、nonce、created_at，
revision=2，previous_hash=H1，state=1，其他字段按作者编辑。

暂停请求：[1,0,1,R7,512,[[B2,S2]]]
暂停响应：[1,1,1,R7,200,[C32,2,H2,0,2,H2,1]]
```

撤下需要另签 state=2 的后继版本。不能在 B2 外加一个“撤下”元字段绕过作者签名。暂停允许后继恢复，撤下不允许。

### 4.6 错误与新请求

```text
暂时限流：[1,1,1,R8,429,["rate_limited",3600,nil]]
版本过时：[1,1,1,R8,409,["stale_revision",nil,[2,H2,1]]]
游标过期：[1,1,2,R4,410,["cursor_expired",nil,nil]]
```

前两条是独立情境，不是同一 R8 的两个合法终态响应。收到已记录的 429 后到期重新提交，使用新请求 ID；没有收到任何终态时才沿用原 ID查结果。

### 4.7 服务发现与目录同步

```text
发现目的地：trailmate.geocache.directory（标准 Reticulum 派生）
announce app_data：[1, DELIVERY16, EPOCH16, 1, "示例公共目录"]

目录 B 首次同步目录 A：
请求：[1,0,4,R9,2048,[nil,20]]
响应：[1,1,4,R9,200,[0,EPOCH16,[[C32,1,H1,0]],DELTA_CURSOR,0,2592000]]

假设此基线只有一个对象，DELTA_CURSOR 已切换到增量检查点。
B 用 get 取 H1、验签并公开保存，再持久提交检查点。

以后新请求轮询：
[1,0,4,R10,2048,[DELTA_CURSOR,20]]
如有 v2，响应：
[1,1,4,R10,200,[1,EPOCH16,[[C32,2,H2,1]],NEXT_CURSOR,0,2592000]]
```

R9/R10 为不同 bin[16]；DELIVERY16、EPOCH16 和游标为占位。announce 身份必须同时正确派生发现目的地与 delivery 地址。这里没有面向普通终端的定向推送；新终端自动发现 B 即可查询 A 原先发布的点。

## 5. 最小字节示例与互操作证据边界

一个请求 ID 为 `00 01 02 ... 0f` 的 capabilities 请求：

```text
逻辑值：[1,0,0,bin(000102030405060708090a0b0c0d0e0f),8192,[]]
CMP1 十六进制（26 字节）：
96 01 00 00 c4 10 00 01 02 03 04 05 06 07 08 09 0a 0b 0c 0d 0e 0f cd 20 00 90
```

该例只覆盖应用信封编码，不包含完整 LXMF 外层、真实目的地、公钥和签名。不能据此宣称任何设备已互通。

在文档批准后的实现与验证阶段，必须补充固定公开测试密钥的完整 golden vectors：记录字节、cache_id、revision_hash、作者签名、完整 CUSTOM_DATA、打包 LXMF；由至少两个独立语言实现互验。当前没有开发向量生成器、测试服务或固件原型。

## 7. 异常与恢复验收矩阵（未来执行）

| 编号 | 故障注入 / 边界 | 必须观察到的结果 |
| --- | --- | --- |
| F01 | 保存成功后响应丢失 | 原请求重试重放结果，只有一个对象提交 |
| F02 | 相同请求经 direct 与 propagated 到达 | 底层去重或应用去重，不双写、不双通知 |
| F03 | 改 body 或预算但重用请求 ID | 409 request_id_reused，不执行改后操作 |
| F04 | 不同发送方使用相同请求 ID | 作用域独立，不泄露另一方响应 |
| F05 | 错误发送方伪造响应 ID | 不改变请求状态，不导入对象 |
| F06 | 响应先于本地交付回调 | 业务结果有效；后来的旧回调不回退状态 |
| F07 | 复制消息正文但改一个签名字节 | 422/本地验签失败，旧副本保留 |
| F08 | 非规范整数、数组额外项、非法 UTF-8 | 明确拒绝或安全丢弃，不重新解释签名 |
| F09 | 一字节超过字段/对象/信封上限 | 对应错误，有界处理，无静默截断 |
| F10 | 超大压缩消息、深层数组、伪造长度 | 在资源预算内拒绝，不创建大栈对象 |
| F11 | 同 revision 不同有效 hash | 确认冲突，自动更新冻结 |
| F12 | 更低版本迟到 | 不回退；如揭示分叉则标冲突 |
| F13 | 已知前驱 hash 不匹配 | 冲突而非“更大版本优先” |
| F14 | 先收跨越版本，后得矛盾历史 | 从历史未完整转成冲突，不保持假定可信链 |
| F15 | archived 后的更高版本先到 | 旧 archived 证据到达后识别冲突 |
| F16 | 翻页过程中有人更新目录 | 仍读原快照，或明确 410，不静默换快照 |
| F17 | 游标重启失效/参数被改 | 410/400，无第一页数据伪装成续页 |
| F18 | 响应字节预算不足 | 413；不得空页循环或超预算回包 |
| F19 | 摘要与有效对象内容不同 | 不完成摘要对应下载，提示来源不一致 |
| F20 | 来源删除副本后 get | 404，客户端保留本地内容，不宣布作者撤下 |
| F21 | 本地写盘失败 | 不显示已下载，旧版本与个人记录完整 |
| F22 | 接收方事务任意阶段掉电 | 恢复后成功结果与持久对象一致，不提前 200 |
| F23 | 停止等待后响应到达 | 迟到确认；不继续分页、不恢复取消批量任务 |
| F24 | 429 结果后立刻重发相同 ID | 窗口内已接受请求重放原结果，不重新执行 |
| F25 | 去重窗口到期 | 可重新求值，但 publish 不回退/重复建点 |
| F26 | 传播超过提醒时间 | 显示未确认，不断言失败或自动群发 |
| F27 | 作者时间为 0 或回退 | 版本依据 revision/hash；不伪造作者时间 |

| F30 | 设备无法承担 v1 上限 | 不宣告 v1，不推出同名截断实现 |

## 8. 持久化与身份验收重点

验收必须覆盖以下掉电位置：消息已接收但应用未开始、对象写入中、对象写完但当前指针未提交、结果写入中、结果已写但响应未发送、响应已接收但本地正文未提交。

这些是行为约束，不提前指定数据库/文件布局。任何方案都必须证明恢复后不会出现“已确认成功但无对象”“旧版本覆盖新版本”“重复 publish 变成两个点”“个人记录跟随索引丢失”。

身份测试还应覆盖相同显示名不同密钥、相同签名公钥但不同完整公共身份、外层源目的地与内层作者不同、作者私钥缺失、恶意短公钥、非法 Ed25519 表示。是否采用来源白名单不能弱化对象签名验证。
