# 请求生命周期、取消与持久恢复契约

状态：**设计进行中的明确候选，待用户评审；未授权开发**。日期：2026-09-15。

本文件补充协议 01 §9–13 和公共发现 04 §6 的应用行为，不新增线上操作或字段。01 与 04 仍定义线格式；本文是请求与持久恢复的行为规范。后续发现冲突须同步修订，不允许实现者择其方便版本。

## 1. 四种状态不能合并

| 对象 | 身份 | 所有者 | 成功意味着 |
| --- | --- | --- | --- |
| 用户发布/下载任务 | 本机 task_id，不上线 | Geocaching 应用 | 按任务规则汇总子请求，不是单条消息交付 |
| 入口应用请求 | 目标+本机来源+request_id | 应用请求账本 | 获得可关联且合法的终态响应 |
| LXMF 投递尝试 | 标准 LXMF 消息身份 | 现有传输 owner | 按栈事实交付；不代替业务成功 |
| 本地对象接受 | cache_id + revision_hash | 对象存储/版本 owner | 已验证并持久保存；不受页面是否打开影响 |

task_id、本地事件序号和取消标记不上线。应用不能伪造 LXMF Delivered；栈不能替应用宣布 publish 已公开。

## 2. 出站请求状态与事件

出站账本保存原始 CUSTOM_DATA、目标、原来源身份、父任务、创建记录、当前结果、所有已关联传输尝试及用户继续意图。原始字节持久提交前不得提交给 LXMF。

| 当前状态 | 事件 | 下一状态/动作 |
| --- | --- | --- |
| Prepared | 磁盘提交失败 | 本地失败，不发消息 |
| Prepared | 磁盘提交成功 | Queued |
| Queued | 栈接受投递并返回尝试身份 | InFlight；持久关联该尝试 |
| Queued | 栈拒绝且明确未入网 | Queued或本地受阻，按原字节稍后尝试 |
| InFlight | LXMF Delivered | AwaitingResult |
| InFlight/AwaitingResult | 提醒期限到达 | Unconfirmed；不认为远端未执行 |
| InFlight/AwaitingResult/Unconfirmed | 合法应用响应 | RemoteResultRecorded |
| 任一未终态 | 用户停止后续尝试 | 保持事实状态，continue_intent=false |
| RemoteResultRecorded | 后来栈失败或超时回调 | 仅追加传输诊断，不回退应用结果 |
| RemoteResultRecorded | 完全相同应用响应 | 去重，无新任务或通知 |

continue_intent 是调度维度，不是远端状态。文案“停止等待”不抹除请求。终态响应可先于交付回调到达；无须等待 Delivered 才接受它。

一次“原请求重试”保留应用字节和 ID，外层 LXMF 可不同。收到终态拒绝后想重新评估，建立新 ID。更改预算、查询条件、版本或入口同样是新请求。

## 3. 响应合法性与冲突结果

校验顺序：认证来源/本地接收身份 → 未过期关联 → kind=响应 → 版本规则 → operation/request_id → 原预算 → status/body类型 → 操作语义 → 内层对象。

| operation | 可成功状态 | 必须核对 |
| --- | --- | --- |
| capabilities | 200 | 12项能力数组、角色与操作集合一致、上限合法 |
| publish | 200 | 提交 ID/revision/hash 等于原请求对象；当前字段按规范匹配 |
| query | 200 | 快照和页结构、条数、字节预算、摘要范围/类型、游标前进 |
| get | 200 / 304 | 200对象匹配原 ID及精确hash；304只能用于latest且本地已有known_hash |
| sync | 200 | phase、epoch、引用、非空next_cursor、has_more与预算正确 |

错误状态只能使用 01 §13 已定义 token/context。304 出现在非 get、成功响应正文不匹配、响应超预算等均是协议错误，不能成为任务成功。保留有限诊断并暂停该来源当前尝试，不给错误响应再发错误。

同一请求收到两个不同终态正文时：保留首个合法终态为历史结果，记录“来源结果不一致”，暂停该来源的自动继续动作；不覆盖已持久保存对象。需要新请求验证当前事实，不能猜哪个终态更新。来源可被暂时隔离，具体候选池策略须与发现调度契约一致。

**request_id_reused 的特殊边界：**该响应没有携带请求指纹，接收方不能仅凭这个错误推断原合法请求已经失败。收到它后将原请求标记“关联异常/结果未确认”，停止自动重发并保留原字节；若已有合法成功，不覆盖成功。发送实现必须首先禁止自己为相同作用域发不同字节。原合法请求后来收到可验证成功仍可记录，但保留异常诊断。

此处理避免错误变体引出的409抢先终结原请求；它不授权无限重试或对冲突错误自动重新发布。

## 4. 远端结果与本地完成的两阶段区别

收到 get 200 并不立刻代表下载成功。客户端应先验证对象，再把原文、版本事实、来源关系和请求处理结果共同持久提交；之后才显示已下载。写盘失败保留“收到有效响应但本地保存失败”，不回退旧对象。

publish 200 证明远端当时公开接纳。若客户端无法持久记录该结果，不显示可恢复的最终成功；可暂时显示“收到接纳确认，本地记录失败”，恢复后以原请求查结果或用新 get核实。不得为了再次显示成功而生成新 cache_id。

query 200 只导入来源摘要，不能写进作者已验证对象存储。sync 200 只导入待处理引用；整页引用完成接受或已验证去重后才能推进检查点。

## 5. 用户取消与任务聚合

| 用户动作 | 尚未交给传输栈 | 已经交给传输栈 | 迟到响应处理 |
| --- | --- | --- | --- |
| 取消公开发布任务 | 取消未发送子请求 | 停止新入口和应用重试，不能撤回 | 合法200记录迟到公开接纳 |
| 取消批量下载 | 不再启动剩余项 | 本地标记不再安装未完成项 | 验证/记录响应关联，可丢弃未安装正文，不自动导入 |
| 停止查询/离开页面 | 停止自动分页（离开页不等于取消全部后台任务） | 原请求仍关联 | 可保留有界摘要缓存，不重启分页、不抢回界面 |
| 删除已下载副本 | 与该ID进行中的安装协调 | 禁止旧下载任务在删除后复活内容 | 保留不安装标记；需新的用户下载意图才能重装 |

应用给每个安装意图分配本地 generation。响应提交安装时必须校验 generation 仍有效；删除/取消先持久提升 generation，再移除对象引用。这个字段不进入线协议，也不改变 cache_id。

取消只影响应用调度；如栈提供安全的单次取消接口可尝试，不能关闭共享链路、停止其他聊天任务或宣称已从传播网络删除消息。

发布任务汇总：至少一个匹配当前提交版本的入口200即公开接纳；其他入口失败不能回退。发布新版本是新任务，不能把旧版本200计入新版本成功。界面显示每个版本的结果；当前作者草稿和已公开版本独立。

未入网的已签名版本可以保留不发布，但它的revision不可再用于另一份内容；下一次作者签名必须按本地签发记录递增。若决定废弃一个未发布版本，允许后继成为跳号快照，保留前驱签名记录。不能删除未确认版本后重用同revision制造分叉。该候选规则需在作者编辑页明确告知，并纳入版本验收。

## 6. 时间、过期与无可信时钟

- 同一启动周期的提醒和退避使用单调时间；系统时钟校正不造成连发。
- 持久保留期使用记录的本地接纳时间和“可证明已经过去的时长”，不使用作者时间或对端LXMF时间戳决定GC。
- 重启后有可信RTC/已验证系统时间可计算保守剩余期；没有可信时间时按“尚未证明到期”保留，恢复单调计时，不立即删除请求/正文。
- 时钟向后跳只能延长保留，不能缩短承诺；向前跳且未经时间owner确认不得提前GC。容量不足拒绝新接纳，不以时钟未知为理由删除旧承诺。
- query/sync 返回的 remaining_ttl 是响应生成时快照，不是接收时新租约；迟到重放不刷新本地游标年龄或服务端期限。
- 缓存过期只影响是否需要重新发现/查询，不证明记录失效或作者撤下。

第三方可使用更强的时间基础，但必须保持相同保守语义。具体设备 time port 必须暴露时间可信度；仅有毫秒 tick 不能冒充跨重启的30天耐久时钟。

## 7. 接收方事务与并发顺序

每个本地应用实例对相同 request_key 和 cache_id 的提交串行化。对象锁/事务在存储owner中，不由UI持有；不能持锁等待网络。

| 事务 | 必须同时可恢复的事实 |
| --- | --- |
| publish 新版本 | 原签名对象、版本选择/冲突状态、公共索引可重建事实、目录日志引用、保留期限、请求指纹与终态结果 |
| publish 重复当前版本 | 续期事实（如新请求）、成功结果；不追加重复变化日志 |
| 接受下载 | 原文、版本事实、来源、有效安装generation、请求处理结果 |
| 同步接受对象 | 原文、版本/证据、公共可读事实、本目录新日志及保留期 |
| 同步推进一页 | 所有引用已处理证明、下一检查点、旧页完成标记 |

两个入口请求同时提交同版本时，仅一个创建版本/追加日志，另一个得到已存在结果。两个不同有效版本同时到达，按事务串行顺序处理并再次检查所有相关历史，不允许因都读到旧头部而分别覆盖。

同一对象的新版本与GC并发时，GC只能根据提交后的引用集合删除；未提交事务的临时对象受事务保留标记保护。最终采用数据库事务或日志文件由设备存储设计定义，但不能改变这些原子集合。

## 8. 保存承诺、重复发布与清理

原请求重放返回原结果，**不续期**。新request_id提交同一当前对象并得到disposition=1时，从新接纳时刻重新保证至少30天公开保存；不追加重复内容日志，但持久更新保留期限。

get、query本身不无限续租对象；创建快照/提供同步游标会按明确承诺将必要原文保留到对应期限。不能因只读者重复轮询而无上限续租全部历史；源需在创建承诺前预留容量并可限流拒绝。

清理条件必须同时满足：最低接纳保留期到期、没有未到期快照/日志/请求结果所需引用、不是当前冲突证明或受保护作者签发记录、不被本机用户下载/个人引用策略固定。目录的普通旧正文可以清理，但失去原签名正文的历史不能再被伪称为可独立验证的冲突证据。

本地删除副本只删除用户内容引用，不自动删去防回退元数据、未确认请求、个人记录或作者签发账本。若用户明确执行完整清除，应提示会丢失这些本地记忆；它不是撤下命令，网络副本仍存在。

## 9. 掉电恢复矩阵

| 掉电位置 | 重启后必须做什么 | 禁止出现 |
| --- | --- | --- |
| 请求Prepared未提交 | 丢弃未提交意图，或恢复草稿 | 自动发送半份请求 |
| 出站请求已提交但未知是否入栈 | 原字节重试/查询结果，允许网络重复 | 生成不同内容复用ID |
| publish对象临时写入但事务未提交 | 回滚或按完整日志重做，暂不公开 | 无完整事务却回成功 |
| 对象已写、索引未完成 | 从提交日志重建，服务恢复后再响应 | 私下保存却已回200 |
| 请求结果已提交、响应未发 | 重放已保存的终态响应 | 重做副作用或换成新的current结果 |
| get对象写入中 | 保留旧版本；临时正文验证/提交后才可用 | 列表先显示已下载 |
| sync页部分引用完成 | 保留逐项处理记录，重试剩余引用 | 把next_cursor当已经完成 |
| 页面取消已提交、旧下载完成 | 安装generation不匹配，拒绝安装 | 用户删除后内容自动复活 |
| 快照状态丢失 | 返回明确410；重建不会删除客户端对象 | 旧游标悄悄指向新页 |
| 目录日志连续性丢失 | 新epoch并要求重建基线 | 保留旧epoch假装增量连续 |

耐久提交的定义是经平台存储port确认重启可恢复，不仅是写函数返回或内存索引已更新。无法给出该保证的平台不能回成功。

## 10. 场景推演与验收编号

| ID | 输入顺序 | 预期最终事实 |
| --- | --- | --- |
| L01 | publish成功→ACK丢失→重启→原请求重发 | 一个公开版本，一个原结果，保留期不因重放重置 |
| L02 | 原请求尚未结果→收到request_id_reused→随后合法200 | 记录关联异常，合法200可确认接纳；不被409永久抢占 |
| L03 | get接收中→用户删除该ID→响应完成 | generation失效，正文不自动重装 |
| L04 | 同版本新ID publish，两请求并发 | 一个新日志引用，各自合法结果；新接纳续期 |
| L05 | sync本页前两项成功、第三项断网→重启 | 前两项可去重，第三项补齐前不推进检查点 |
| L06 | 请求30天窗口内重启且RTC未知 | 保留账本，拒绝超容量新任务，不能立即过期 |
| L07 | 旧版本正文已GC，仅元数据与新记录矛盾 | 本地历史疑点，尝试取回证据；不制造伪签名证明 |
| L08 | query历史响应30天去重内重放，快照7天已过期 | 返回原响应仍是历史页；后续游标410，不续租 |
| L09 | 远端有效200但本地磁盘满 | 不虚报可恢复下载成功，旧对象保留 |
| L10 | 同请求先合法200后不同合法错误 | 不覆盖首结果；隔离来源异常并停止自动继续 |
