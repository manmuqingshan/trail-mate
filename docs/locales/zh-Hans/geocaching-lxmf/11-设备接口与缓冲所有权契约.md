# 设备接口、缓冲所有权与展示绑定契约

状态：设计候选，待评审，未实现。日期：2026-09-15。本文不新增线上字段。

## 1. 从源码事实到拟议接口

当前 [IIncomingDeliveryCommitPort](../../../../modules/core_chat/include/chat/ports/i_incoming_delivery_commit_port.h)仅提供 commitIncomingText；[LxmfDeliveryRuntime](../../../../platform/esp/arduino_common/include/platform/esp/arduino_common/chat/infra/lxmf/lxmf_delivery_runtime.h)的 kind 只有 Text/AppData。它们不能未经改造就被描述成已经支持本协议的通用应用接收端口。

本稿把需要新增的契约定义为语言无关接口，不提前创建C++符号。真正挂载位置要按GitNexus影响分析和现有owner确认后实施，不能在Geocaching页中插入第二条收包路径。

## 2. 类型与传递规则

| 逻辑类型 | 内容 | 生命周期 |
| --- | --- | --- |
| Destination | 完整16字节目的地hash | 按值保存，不以NodeId代替 |
| CacheId / RevisionHash | 各32字节，类型区分 | 按值传递或持久保存 |
| RequestId | 16字节 | 出站请求寿命内固定 |
| LocalOperationId | 本机不透明ID | 请求/存储/签名调用关联，不上线 |
| PayloadLease | 有界字节缓冲/文件切片的拥有句柄、长度、释放方法 | 显式移交所有权，一次释放 |
| ViewBytes | 指针/长度借用视图 | 只在同步调用期间有效，不能排队保存裸指针 |
| VerifiedPeer | 身份验证结果、完整公钥、目的地关联 | 由现有身份owner产生，不由应用根据字符串构造 |

PayloadLease不要求堆分配，可以是池槽或存储reader句柄，但必须满足长度、只读和失效检测。最大应用数据8192字节，record_bytes最大4096；两个上限分别检查，不能借元数据绕过。

## 3. LXMF应用传输port

### 3.1 提交发送

逻辑输入：LocalOperationId、原来源身份引用、Destination、CUSTOM_TYPE、PayloadLease、交付策略、请求账本关联。输出分为即时结果与异步事件。

| 即时结果 | 所有权 | 语义 |
| --- | --- | --- |
| Accepted | lease移交传输适配器 | 只证明接受排队，不证明入网/交付/远端保存 |
| Busy / NotReady / Unsupported / InvalidInput | lease仍由调用方拥有 | 本次未被接受，不产生异步完成回调 |

Accepted之后必须产生一次终止事件并释放lease，或把该操作转入持久可恢复队列。事件可包括Queued、InFlight、Delivered、Failed、CancelledBeforeSend；栈的真实消息hash就绪后发布绑定事件，不能用LocalOperationId伪造hash。

传输owner可执行自身合法重试，但不能重写CUSTOM_DATA、请求ID或标点版本。应用重试必须先确认上一尝试已终止或交由同一owner合并，禁止页面/核心/适配器各自重复计时发送。

发送需要的外层字段、title/content由一个封装入口生成；Geocaching核心只提供规范应用字节。核心不访问私钥或拼接Reticulum包。

### 3.2 接收与确认

统一验证入口产生：本地完整目的地、源完整目的地、VerifiedPeer、标准LXMF消息hash、接收交付方式、CUSTOM_TYPE与应用PayloadLease。只有外层验证有效且类型匹配才进入本协议owner。

接收分三种结果：

- **DurablyOwned**：已将接收字节及消息身份持久纳入可恢复应用队列，允许底层执行其持久接收确认。
- **RetryLater**：未持久取得，不发业务成功，不把传播检索标记为已接受；释放/重试由原owner掌握。
- **DurablyDiscarded**：认证后确认是永久无效/不支持且丢弃决定已由统一账本记录，底层可以停止重复交付；不等于对象已接受。

具体确认动作必须复用现有消息/传播owner。不能直接从业务层向传播节点发送ACK，不能为避免重复而先ACK再异步试图写盘。

### 3.3 与聊天共存

外层先验证，再按应用类型分流。有效匹配本协议的消息进入专门业务投影，不生成普通聊天未读；原始消息去重与持久交付仍使用共同owner。未知CUSTOM_TYPE交回宿主既有处理策略，不被本协议吞掉。认证失败不通过把文本显示成功来绕过验证。

## 4. 身份、签名、时钟与随机源port

| 操作 | 输入 | 成功输出 | 失败处理 |
| --- | --- | --- | --- |
| 获取本机作者身份 | 身份引用 | 完整公共身份与稳定引用 | LocalIdentityMissing，保留草稿 |
| 对精确字节签名 | 身份引用、带域原字节lease | 64字节Ed25519签名 | 不发布未签对象，不换身份重试 |
| 验证作者签名 | 公钥、原字节、签名 | Valid / Invalid | 算法/资源Unavailable与Invalid分开，不误指控作者 |
| 生成随机字节 | 16字节需求 | CSPRNG输出 | 无安全随机源则不创建nonce/request_id |
| 时间快照 | 无 | 单调tick、boot_id、可选UTC及可信度 | 无可信UTC按10 §6保守保留 |

签名期间身份切换不能让结果混入另一个作者记录。准备签名时固定身份引用，返回时核对引用仍对应记录公钥。私钥不通过core、UI或日志传播。

## 5. 存储port

核心提交“事务意图”，具体文件或数据库实现由平台实现。即时接受排队不等于耐久提交。

| 调用 | 输入 | 异步结果 |
| --- | --- | --- |
| 提交事务 | LocalOperationId、预期版本/generation、事实变更及拥有的原文 | Committed / Conflict / NoSpace / Unavailable / Corrupt |
| 打开对象reader | 完整revision_hash | 只读有界reader或NotFound，不返回无生命周期裸指针 |
| 读取视图页 | 过滤、排序、视图generation、上限 | 固定数量结果与truncated/续页标志 |
| 生命周期恢复 | 平台启动与挂载状态 | Hydrating / Ready / ReadOnly / Unavailable / Corrupt |

Committed表示事务中所有事实重启后可恢复；Conflict是预期版本或安装generation已失效，应重新读事实，不盲目覆盖。NoSpace不得靠删除未到期承诺自动重试。

对象reader读到的内容在reader释放前被保留，GC不能删掉一半；调用方不用持有SPI锁。共享存储维护owner决定IO安排，UI不得绕过 hydration。

## 6. 执行上下文与生命周期

核心应用命令在单个逻辑执行序列处理。栈、存储、签名异步回调只提交小型事件句柄，不能在无线回调里执行大对象解码、UI创建或长时间写盘。队列满时返回明确背压，由拥有者保留待处理状态，不静默丢失已承诺操作。

LVGL线程只读不可变snapshot、提交动作；后台不得直接改LVGL对象。snapshot按双缓冲/受控发布切换，读方生命周期明确；方式是实现选择，行为是固定约束。

关闭顺序：停止接受新用户动作 → 持久continue_intent和未完成任务 → 停止本功能新发送 → 等待或安全移交已拥有lease → 刷新可提交事务 → 注销回调 → 销毁页面/适配对象。不得销毁owner后再让旧回调访问释放内存。

切换协议离开Reticulum：在线任务进入暂停/不适用状态，保留已入网未知结果与账本；已下载仍可用。切回时恢复原请求关联，不把用户已经停止的任务自动重开。

## 7. 展示与动作契约

source提供：列表页snapshot、单对象详情snapshot、活动状态snapshot、地图覆盖snapshot。每份有valid、generation和范围；只有UI必要的摘要进入快照，不把4096字节描述复制到每个列表项。长正文用有界文本页读取。

action sink 的立即 success 只表示动作已接受排队。公开接纳、下载完成、保存错误通过后续snapshot显示；不得把现有UiActionResult::success当成远端成功。

动作至少包含：查询区域、加载下一页、下载指定版本、检查更新、保存草稿、签名并发布、停止后续尝试、删除副本、保存个人记录、打开选中点、申请地图目标。输入携带完整ID/版本或下述可校验选择句柄。

## 8. 地图选择身份：明确采用有界句柄候选

本稿选择08中尚未决定的一种方案：**渲染项保留小型句柄，完整业务引用存在同一代际的有界映射表**。这是新增设计候选，不是已实现接口。

- MapSelectionRef包含snapshot_generation:uint64、slot:uint8；slot只在本快照0..31有效，不上线、不跨重启保存。
- 该代际映射表保存kind、完整cache_id、revision_hash及摘要/已验证标志；32项上限不变。
- 地图点击/确认带回generation和slot。仅当前仍持有的对应代际可解析，失效时返回StaleSelection并刷新显示，不用slot打开其他点。
- 现有uint32 stable_id仍可供旧覆盖项使用，但不作为藏宝点权威身份；需要改造选择回调承载新引用，不能只把hash截断塞进去。
- 跳转详情时立即解析并复制完整ID/hash到详情会话。后续地图刷新不让详情切换成另一个点。
- 恢复地图选中项保存完整cache_id而非slot；投影后重新寻找对应槽位。

容量统一由覆盖组合器分配，候选优先级已在20 §5明确：自身、目标、当前选中、警告/测距、现有队伍/路线、藏宝点，去重后最多32项并标截断。每个source不能独立抢满容量。实施前仍需影响分析，不能把候选规则当成当前代码事实。

## 9. 接口验收

| ID | 情况 | 期望 |
| --- | --- | --- |
| I11 | transport返回Busy | 调用方仍拥有lease，无迟到“完成”回调 |
| I12 | transport接受后页面销毁 | 传输与账本继续；无页面悬空指针 |
| I13 | 入站写盘失败 | 不发持久接收成功确认，业务不执行未恢复消息 |
| I14 | 身份切换发生在签名期间 | 不把旧身份签名配到新公钥记录 |
| I15 | snapshot刷新后点击旧slot | StaleSelection，不能误开新点 |
| I16 | 存储返回Conflict | 保留旧事实，重新读取，不覆盖并发删除 |
| I17 | 收到Geocaching响应 | 无普通聊天未读，但有统一消息去重事实 |
| I18 | 切换协议后旧响应返回 | 安全关联结果，不重开已停止任务 |

这里的接口名称/类型为明确的逻辑契约；真实C++声明、目标注入点及构建变更在完成源码影响分析后映射。本文解决所有权与调用语义，不伪称已完成平台预算或文件格式设计。
