# 寻宝GPX扩展兼容配置

状态：根据实际schema核对形成的候选，尚未完成第三方软件实测。与17基础GPX和作者扩展共同使用。

## 1. 选择

默认用户GPX建议同时提供：标准GPX1.1字段、Groundspeak 1.0.1语义扩展、本应用作者原文扩展。前两者服务已有软件，最后一项保留Reticulum公开对象身份与签名。

使用既有扩展namespace只表达其定义的字段，不声称内容来自Geocaching.com。不得伪造GC代码、网站缓存数字ID、平台owner账户ID、页面URL或日志。兼容目标是能正确读取真实字段，而不是借假身份诱使软件加载。

## 2. 取得的来源

从官方地址取得并保留原文：[1.0.1 schema](https://www.groundspeak.com/cache/1/0/1/cache.xsd)、[1.0 schema](https://www.groundspeak.com/cache/1/0/cache.xsd)。本地副本见[1.0.1](./references/groundspeak-1.0.1.xsd)与[1.0](./references/groundspeak-1.0.xsd)。此前网页工具访问失败不是schema不存在；本轮通过HTTPS实际读取并解析成功。

1.0.1定义cache/name、placed_by、type、container、difficulty、terrain、description和encoded_hints等字段；owner/id注释明确对应平台账户。本稿不生成owner/id。cache的id/available/archived是可选字符串属性，schema没有强制要求平台数字ID；但真实客户端可能有额外假设，须单独测试。

## 3. 默认生成映射

groundspeak:cache作为wpt/extensions子元素，与tm:record并列。namespace精确为 `http://www.groundspeak.com/cache/1/0/1`。字段顺序遵循schema；prefix可任意，解析按URI判断。

| 字段/属性 | 生成规则 |
| --- | --- |
| cache/@id | 省略；完整本协议ID在标准desc与tm原文中，不伪造平台数字ID |
| cache/@available | active为`True`，disabled/archived为`False` |
| cache/@archived | archived为`True`，其他`False` |
| name | 原作者name |
| placed_by | `Reticulum author ` 加完整公共身份的SHA-256小写hex指纹；它是自由描述，不是平台账号 |
| owner | 省略，避免平台账户关联 |
| type | `Traditional Cache`，与当前单地点实体容器范围一致 |
| container | 0=`Not chosen`，1=`Micro`，2=`Small`，3=`Regular`，4=`Large`，5=`Other` |
| difficulty / terrain | x2值除以2，固定1位小数 |
| short_description html="False" | `Public cache shared over Reticulum.` |
| long_description html="False" | 原description，不包含HTML，不重复机器解析控制块 |
| encoded_hints | 原hint明文；schema注释说明GPX中以明文显示，不能额外ROT13导致中文/提示错误 |

country、state（地理州省）、attributes、logs、travelbugs省略，因为协议没有这些事实；不得把作者维护state写进地理state元素。GPX的name继续用用户可读名称，不生成GC前缀代码。

## 4. 文件示意

```xml
<groundspeak:cache xmlns:groundspeak="http://www.groundspeak.com/cache/1/0/1"
                   available="True" archived="False">
  <groundspeak:name>林间小盒</groundspeak:name>
  <groundspeak:type>Traditional Cache</groundspeak:type>
  <groundspeak:container>Small</groundspeak:container>
  <groundspeak:difficulty>1.5</groundspeak:difficulty>
  <groundspeak:terrain>2.0</groundspeak:terrain>
  <groundspeak:short_description html="False">Public cache shared over Reticulum.</groundspeak:short_description>
  <groundspeak:long_description html="False">在步道旁寻找一个小型容器。</groundspeak:long_description>
  <groundspeak:encoded_hints>留意树根附近。</groundspeak:encoded_hints>
</groundspeak:cache>
```

示意省略placed_by避免伪造示例作者；完整作者文件按表生成。示例只是扩展子树，不是假装已签名的完整GPX。

本轮使用lxml XMLSchema对上述实际XML子树及下载的1.0.1 schema执行assertValid，结果为SCHEMA PASS。只证明该子树结构合法，不证明客户端会将缺少平台数字ID的独立记录识别为原生geocache。

## 5. 验证和外部修改

GPX基础schema采用lax扩展处理，仅验证整份GPX不够；还需对groundspeak:cache子树单独用1.0.1 schema验证，再按本稿语义检查枚举和难度范围。字符串schema允许任意文本，不代表每种文本业务有效。

扩展存在且作者签名有效时，所有从原文映射的groundspeak字段也必须一致；外部软件改难度/提示/状态，不能因基础wpt未变而继续显示为原作者内容。省略非作者事实字段如placed_by或改变prefix不属于作者内容修改。

普通GPX带有Groundspeak扩展但没有tm签名时，可读取寻宝字段用于本地展示，但仍是未验证外部导入。不得使用groundspeak:id当成本协议cache_id，也不得自动把其owner当本地可签发身份。

## 6. 不兼容客户端的边界

有些客户端可能要求GC形式的name或平台数字id。对这类软件，不能为“兼容”造假编号；应在兼容矩阵中记为基础waypoint可用/原生geocache不支持，并保留完整描述。需要单独的厂商适配格式时，必须依据真实接口和用户评审，不自动污染默认GPX。

默认只生成1.0.1；不同时输出两份1.0/1.0.1 cache导致重复识别。导入可识别两版namespace，按实际存在版本分别解析；同一个wpt出现两份互相矛盾的cache扩展，标记导入歧义而不是任意覆盖。

本候选提供明确的寻宝扩展字段，不宣称所有软件已经原生兼容。下一步是带签名完整样例、schema验证和软件导入证据；不能以本文件存在关闭全部G23。
