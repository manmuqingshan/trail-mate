# 公共发现调度与同步失败契约

状态：设计补全候选，待评审，未实现。对应线协议1，不新增线上字段。

## 1. 适用范围

本文细化04的自动发现与复制，解决候选过多、恶意引用、部分成功、游标失效与重启时的处理。公开访问不等于无限资源；所有限制必须可观察，不能把反滥用变成私人读者名单。

本稿的池容量和调度参数是待评审的产品默认，不是全网规模限制。不同实现可调整本地容量，但不得修改消息上限、游标语义或宣称未查询部分也已同步。

## 2. 目录候选池

候选键为完整发现目的地hash；只有原生announce验证和同身份delivery绑定通过后才进入候选池。同身份重复announce更新记录，不新增副本。

| 本地配置 | 手持客户端默认 | 公共目录默认 |
| --- | --- | --- |
| 候选总数 | 32 | 256 |
| 单次能力检查并发 | 1 | 1 |
| 已验证候选单轮查询/同步 | 最多3个，串行 | 最多3个，串行 |
| 无成功通信且无新有效announce的候选老化 | 7天 | 7天 |
| 能力缓存 | 24小时 | 24小时 |
| 同一候选能力失败退避 | 1分钟、5分钟、30分钟，之后6小时 | 相同 |

满池时优先移除已过期且无在途请求的候选，其次最久未成功通信且无在途请求者；仍无法腾出则拒收新候选并增加本地发现截断计数，不终止已接受请求。显示名不参与优先级。删除候选不删除对象来源证据或请求结果账本。

公平轮转通过持久的轮转位置与每候选last_scheduled记录实现，成功者不能无限占据前三位。目录更新sequence可以标记dirty，但每候选同时只有一个合并的dirty意图，不能每个announce制造一个任务。

同epoch的更低sequence不回退本地检查点；更高sequence只提示可能有新数据。epoch改变先进行能力和sync核实，不因announce直接删除本地对象。频繁改变epoch仍受同一身份退避和池限制。

这些限制不能抵御无限新身份的Sybil攻击；本地可以进一步限流、配置可信种子，但不得声称某来源白名单代表全网目录。未进入池的目录不在当前可见性保证范围。

## 3. 来源健康状态

| 状态 | 进入条件 | 调度规则 |
| --- | --- | --- |
| Candidate | 有效服务announce | 排队检查capabilities |
| Ready | 公共角色及能力合法 | 按公平轮转使用 |
| Backoff | 超时、路径失败、429/503 | 到期再发新请求或恢复未知请求，依据10区分 |
| Quarantined | 无效对象、反复违反游标/保留承诺、矛盾响应 | 不自动继续该轮；保留诊断，6小时后仅重查能力一次 |
| Incompatible | 版本或公共能力不支持 | 新能力信息/用户刷新后重新检查，不循环请求 |
| Expired | 老化且无在途任务 | 可移出候选池 |

Quarantined不是永久禁止读者访问，而是本机对来源可靠性的保护。再次出现同类违规继续隔离；用户可明确重试，但不得跳过签名和字段验证。暂时网络错误不记成恶意内容。

## 4. 同步会话持久状态

每个远端目录保存epoch、最近已提交检查点、当前页请求字节、已收到的完整页、页内项目处理标记、候选下一游标、剩余期限证据和失败状态。会话不按普通聊天会话组织。

每项ObjectRef处理状态只有：Pending、Fetching、Accepted、AlreadyVerified、EvidencePending、FailedTransient、FailedPermanent。只有Accepted/AlreadyVerified可以计入页完成；EvidencePending不能被悄悄当完成跳过。

接受旧但有效、不构成冲突的引用可记AlreadyVerified/AcceptedHistory：必须有足够本地验签事实确定它不改变当前，不要求把旧版本重新公开为当前。该情况不追加重复当前日志，但若属于远端仍有效快照承诺则不得伪称未取得的原文已验证。

## 5. 失败动作总表

| 事件 | 当前页处理 | 检查点 | 后续动作 |
| --- | --- | --- | --- |
| 请求无终态，网络断开 | 保留请求和页进度 | 不推进 | 原请求重试，遵守退避 |
| 429/503合法终态 | 保留页和未完成引用 | 不推进 | 等待后新请求ID，仍用对应游标/精确hash |
| sync 410 | 终止该快照页，保留已验对象 | 不把旧next当新检查点 | 新请求cursor=nil重建基线 |
| sync返回epoch与当前分页不一致且非正常重建 | 标为协议违规 | 不推进 | 隔离来源，随后重建 |
| get 404但此前引用仍在保留期内 | 对该项记录保留承诺失败 | 不推进 | 尝试其他已知提供者同hash；否则中止本轮并隔离来源 |
| get正确对象但签名无效 | FailedPermanent | 不推进 | 隔离来源，不再自动下载该页 |
| get有效对象却ID/hash不符 | FailedPermanent | 不推进 | 隔离来源，不能拿另一对象补数 |
| 本地磁盘满 | FailedTransient | 不推进 | 暂停所有新复制，等待容量恢复 |
| 本地已持有同hash已验原文 | AlreadyVerified | 页全完成才推进 | 不重复get、不重复日志 |
| 本地发现有效分叉证明 | Accepted（冲突证据已持久提交） | 页全完成可推进 | 冻结该ID，公开传播证明 |
| 仅历史元数据矛盾、旧原文缺失 | EvidencePending | 不推进 | 按旧hash取证；不可得则中止本轮，保持历史待核实 |
| 页预算用完但仍有未处理项 | 保留页 | 不推进 | 下轮续当前页，不重新发起全库同步 |
| 用户关闭目录复制/退出角色 | 持久暂停 | 不推进未完成页 | 不删除已接纳对象和保留承诺 |

中止本轮与提交检查点不同：中止允许以后主动从nil重建，不宣称坏页已经成功处理。保持未完成引用的有限诊断，不能无限增长待失败列表。

## 6. 有限重建与坏页防循环

每个来源每24小时最多自动重建基线一次；若同一epoch内连续两次基线因相同(C,H)引用失败，进入Quarantined，不继续自动“从头再来”。其他来源仍可复制该对象，但必须同hash验签。

一次来源恢复检查不清除已知坏对象证据。只有后续合规响应和成功页处理才能恢复Ready；capabilities正确仅证明角色兼容，不证明数据已修复。

本地诊断每来源保留最近16条失败摘要（ID/hash、原因、时间），旧诊断可滚动；请求终态、对象冲突证据和有效保留承诺不能跟随诊断滚动删除。

若来源只剩一个，仍不能为保持“同步成功”而跳过签名或跳过坏页。界面报告同步受阻和覆盖不足，保留其他已下载可用内容。

## 7. 游标桌面推演

### 基线期间发布

基线建立时高水位P=10，包含C/H1。目录在基线传输期间接纳C/H2，日志11。基线最后游标从10继续；下一次增量必须返回11。实现若从“基线完成时最新序号11”开始，会漏H2，验收失败。

### 增量中途新增

从P=10轮询捕获Q=20，每页5项。第二页尚未读取时新增21。当前两页仍固定至20；完成后的检查点为20，下次轮询才含21。不得把第一页面向Q=20的next_cursor改到21。

### 旧响应重放

第一次sync响应和其游标已过期，但请求结果仍在30天窗口内。重发相同请求返回原字节；remaining_ttl仍是当时值，不意味着续期。下一请求收到410便重建，不能用原值延长服务端快照。

### 部分落盘与重启

一页引用A/B/C，A/B已接受，C下载中掉电。重启恢复页与A/B完成标记，再取C。A/B可依据持久对象hash去重；C没有Committed就不能推进next_cursor。

## 8. 操作错误优先级

为减少实现分歧，处理请求时按以下顺序，首次确定错误即停止，不继续执行副作用：

1. 外层身份/签名及资源边界；不可安全处理则丢弃。
2. 信封可解析性、版本、kind、ID、预算与类型；安全可关联时按400/426。
3. 原请求账本命中：同字节重放；不同字节409 request_id_reused，不重新执行。
4. 角色支持操作：501；正文结构/参数：400。
5. 对象schema未知：426；已知结构/大小非法：422/413；结构合法后的作者签名无效：422。过载前置保护允许安全丢弃，不能把暂时无法验证当成签名无效。
6. 本地接纳策略/配额：403/429/503。
7. 业务版本/对象存在/游标期限：按操作的404/409/410。
8. 持久提交成功后才产生200/304；提交失败503（有能力持久记录错误时）。

query/get/sync没有内层提交对象时跳过第5项。对于请求只含未知ID，404不说明全网不存在。错误body/context必须按01定义，不把本地诊断字符串发给远端当协议数据。

## 9. 验收补充

| ID | 事件组合 | 预期 |
| --- | --- | --- |
| S01 | pool满且所有候选在途 | 拒绝新增并记录截断，不清除已接受任务 |
| S02 | 一个目录持续announce | dirty合并，其他Ready同伴仍被公平调度 |
| S03 | 同一坏引用导致两次基线失败 | 隔离来源，不无限从头下载 |
| S04 | A/B已提交，C失败后重启 | 保留A/B与检查点，补C后再推进 |
| S05 | sync快照创建后新增日志 | 完成基线后增量不漏新增 |
| S06 | 旧sync结果重放 | 原字节不续租，过期游标410 |
| S07 | 来源给有效签名但错hash对象 | 不接受替换，隔离来源 |
| S08 | 坏来源被隔离，其它来源有同hash | 可从其他源取得并独立验签，不跳过验证 |
| S09 | 只有一个坏来源 | 显示受阻，不虚报同步完成 |
| S10 | 本地NoSpace | 暂停新复制，不删未到期承诺来换200 |

本文件补全G02/G10/G11/G21的一组明确候选；池参数与资源总预算仍需后续统一复核。没有实现同伴调度器或协议原型。
