# Sequence Diagram: ACK, timeout and final state competition

```mermaid
sequenceDiagram
  participant Backend as Protocol Backend
  participant Timer as Timeout Policy
  participant Ledger as ChatMessageLedger
  participant Store as Message Store
  Backend->>Ledger: Sent(messageKey)
  par protocol receipt
    Backend->>Ledger: Delivered(messageKey, receipt)
  and timeout
    Timer->>Ledger: Failed(messageKey, timeout)
  end
  Ledger->>Ledger: merge facts; protect terminal state
  Ledger->>Store: persist winning transition
  Store-->>Ledger: Durable / Deferred / Rejected
```

Ledger determines the final visible state; the callback arrival sequence cannot directly become the business state.

## Competition Scenario

Protocol receipts and timeouts are generated by different execution contexts and can arrive in any order or repeatedly. Both only submit facts and cannot directly change the status fields in the UI or Store.

## Final state merge rules

Ledger reads the current revision and decides according to the partial order of message status. Effective Delivered takes precedence over late timeouts for the same delivery attempt; whether late receipts are accepted after an explicit permanent failure must be determined by protocol policy. Any transition is positioned by messageKey, attempt/generation and expected revision.

## Persistence and Release

The projection is released only after the winning transition is successfully persisted. When Store Deferred, the fact to be submitted is retained; it cannot be notified to the UI first and then rewritten. Rejected indicates that the transition is incompatible with the current state or the input is invalid and a diagnostic should be logged instead of looping and retrying.

## Idempotent

 Repeated Delivered, repeated timeout and retry pump must return the same visible result. An ACK for an old attempt MUST NOT complete a later resent attempt.

## Test matrix

 Covers ACK-first, timeout-first, simultaneous arrival, duplicate ACK, Store Deferred, old ACK after retransmission, and final state recovery after application restart after Delivered.
