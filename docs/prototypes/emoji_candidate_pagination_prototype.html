Emotion Candidate: Classification + Pagination

This is an interactive prototype for about 300 outdoor, radio, navigation and survival semantic emoticons. Classification determines "where to look", and paging ensures that only one screen of candidates is rendered at any time; the two solve search and resource constraints respectively.

300 project catalog → 8 semantic categories → fixed 20–24 cells per screen → page turning within categories
Proof of concept · 320–720 px landscape device screen

A. Classification panel (recommended)

The main interface leaves space completely for a fixed number of candidate cells; the 2×4 classification panel pops up only when "Classification" is clicked.

Most suitable for small screens and hardware buttons: daily selection only requires classification + page turning + confirmation.

B. Permanent category bar

Categories are visible at any time and can be switched the fastest; but if they continue to occupy a narrow screen width, the candidate grid will shrink and the number that can be accommodated on each page will decrease.

Suitable for larger horizontal screens and not recommended as the default solution for 320 px devices.

C. Category homepage

Open the emoticon and enter the "Task Semantic Homepage" first, and then enter the paging grid of the category, where the hierarchy is clearest.

Suitable for new users to understand the catalog; one more time to return/enter when selecting emoticons frequently.
