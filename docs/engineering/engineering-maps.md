## UML drill-down level rules

### package

- Drill-down diagram types: component, class_structural, sequence, deployment, technical_hotspot
- Reason: Package Diagram is the top-level engineering boundary of technical complexity; it can drill down to key components, structural collaborations, running links, running configurations and complexity hotspots within the boundary.

### class_structural

- Drill-down diagram types: component, sequence, technical_hotspot
- Reason: Class / Structural Diagram explains structural collaboration in a nameable business/technical context; it can continue to drill down to specific components, dynamic interaction fragments and structural risks.

### component

- Drill-down diagram types: sequence, class_structural, technical_hotspot
- Reason: Component Diagram is the key technical object perspective; it can drill down to the call fragments, structural slices and related hotspots in which the object participates.

### sequence

- Drill-down diagram types: component, class_structural, technical_hotspot
- Reason: Sequence Diagram is a dynamic collaboration perspective; it can reversely locate participating components, structural boundaries and possible operational risks.

### deployment

- Drill-down diagram types: package, component, technical_hotspot
- Reason: Deployment Diagram is a run/build node perspective; it can drill down to the corresponding package, entry component and run configuration hotspot.

### technical_hotspot

- Drill-down diagram types: package, component, class_structural, sequence
- Reason: Technical Hotspot is a risk perspective; it needs to be linked back to the boundaries, components, structures or call fragments that create complexity.
